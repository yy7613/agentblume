# ADR-0016: 長期記憶を LLM Wiki + Skill蒸留の二本柱で設計する

- Status: **Proposed**（Phase 4 実装。方向性の合意のみ先行）
- Date: 2026-07-05
- Context doc: [docs/10-memory.md](../10-memory.md)

## Context

`ideas-v3.md` がエージェントの**長期記憶**を要求した: 過去の経験・学習内容を保持し将来の意思決定に活用する。手法として **LLM Wiki**（自然言語知識の基盤）と **Skillsベースのアプローチ**（タスク特化知識の強化）の組み合わせが明記されている。`ideas-v2.md §13` では「メモリ・RAG」は保留だったが、これで具体化された。

## Decision

- **二本柱**で設計する: 宣言的知識は新エンティティ `WikiPage`（LLM Wiki）へ、手続き的知識は**既存の `Skill.instructions` への改訂提案**として蒸留する。Skillの資産（バージョン固定・依存Tool・発火条件）を再利用し、記憶専用の別系統を作らない。
- **記憶ループは人手承認制**: Run（実行履歴）→ 抽出 → `MemoryProposal`（差分draft）→ 人がレビュー・承認 → 保存。エージェントによる無承認の記憶書き込みはしない（プロンプト自動生成と同じエスケープハッチ原則）。書き込みは `write` 副作用として監査対象。
- **読み出しは最小コンテキスト**: 検索（v1: キーワード/タグ → M4: 埋め込み）で絞り、要約・制限つきで注入。Wiki全文注入は禁止。
- **`MemoryPort` で検索実装を隔離**: 埋め込み検索へは `ModelProviderPort` の `embed` capability 追加で拡張（暗黙フォールバックなし）。
- 段階は M1（Wiki CRUD+検索+手動アタッチ）→ M2（Run抽出→提案→承認）→ M3（Skill蒸留）→ M4（埋め込み検索）。[10-memory.md §6](../10-memory.md) 参照。

## Consequences

- ✅ ideas-v3 の2要求（保持・活用 / LLM Wiki×Skills）が既存アーキテクチャ（Port/Adapter・バージョニング・承認・監査）の延長で実現できる。
- ✅ Skill蒸留は既存のSkillバージョン発行フローに乗るため、記憶の回帰検証（検証画面）も既存指標で測れる。
- ⚠️ 実装はPhase 4。それまでにRunトレースの蓄積（実装済み）とSkill運用実績が前提となる。
- ⚠️ 抽出（振り返りAgent）の品質はLLM依存。M2で提案の採択率を計測し、低採択なら抽出プロンプトを見直す。

## Alternatives considered

- **会話メモリ（メッセージ要約の自動持ち越し）のみ**: ideas-v3 の「Wiki + Skills」明記に合わず、知識が構造化されない。
- **ベクトルDB直行（RAG専用店舗）**: 検索はPortの実装詳細であり、まずWikiという人が読める器を確立してから埋め込みを足す方が、レビュー可能性・監査性で勝る。
