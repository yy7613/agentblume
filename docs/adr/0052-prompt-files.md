# ADR-0052: モデルへ送る指示文は外部ファイルで持ち、組み立てだけをコードに残す

- Status: Accepted
- Date: 2026-09-22
- 関連: [implementation/v48](../../implementation/v48-prompt-files.md)（契約の正本）/ [ADR-0049](./0049-tool-templates.md)（外部ファイル化の先例）/ [ADR-0033](./0033-agent-factory-generation-loop.md)（untrusted data の隔離）

## 文脈

モデルへ送る指示文が、TypeScript の文字列配列としてコードの中に散っている（約 25 か所）。文を直すたびにビルドが要り、運用者は自分のモデルに合わせて言い回しを調整できず、どこにどんな指示があるかを一覧できない。文の版は別の定数で、文を変えても上げ忘れる。

一方で、この製品のプロンプトは「文」だけでできていない。条件で入れ替わる規則（複数値フィルタの有無・結合の有無）、値の差し込み（上限・言語・カタログ）、そして **untrusted data の隔離**（利用者のデータや指示文を system に混ぜない）は、実測で効いた設計であり、崩してはいけない。

## 決定

1. **文はファイル、組み立てはコード。** `prompts/**/*.md` に frontmatter と `## 節` の形で文を置く。どの節をどの順に使うか、条件での入れ替え、`wrapUntrusted`、JSON schema はコードに残す。
2. **テンプレート言語は持たない。** `{{name}}` の差し込みだけ。条件や繰り返しが要るなら節を分けてコードで選ぶ。文字列で JSON や制御構造を組み立てる事故を避ける（ADR-0049 と同じ判断）。
3. **起動時に全件読み、無ければ止まる。** コードが宣言した id と節が揃っていることを起動時に検査し、揃っていなければどのファイルの何が無いかを出して止まる。実行中は更新時刻で再読込し、壊れたファイルは直前の版を使い続ける。
4. **運用者は別フォルダで上書きできる。** ツールテンプレートと同じ流儀（環境変数・後勝ち・再起動不要）。
5. **版はファイルが正。** 実行記録に残す版の文字列は frontmatter から取る。
6. **人が編集する成果物の雛形は移さない。** エージェントの system プロンプト生成・Skill の文・ペルソナの基底文・回答の規律ブロックは利用者の資産で、保存後に画面で直せる。ここで扱うのは「実装がモデルへ送る指示」だけ。
7. **移行は等価変換。** 文は一字一句そのまま移し、移行前後で組み立てた文が完全一致することをテストで固定する。言い回しの改善は別の増分にする。

## 理由

- **文を触る人と、隔離や組み立てを守る人は違う。** 運用者が文を調整しても、untrusted data の隔離や条件の規則は壊れない。
- **同梱と上書きの二層は、テンプレートで既に動いている。** 同じ仕組み・同じ環境変数の流儀にすれば、学ぶことが増えない。
- **起動時に止まるのは、黙って別の指示で動くより安い。** 節が 1 つ欠けた上書きでモデルの挙動が静かに変わる方が、見つけにくく高くつく。
- **同期の `get` にする理由**: プロンプトの組み立ては多くの純関数の中で行われる。非同期にすると全経路が変わる。起動時に読み終えているので同期で足りる。

## 検討した代替案

- **Handlebars 等のテンプレート言語**: 条件や繰り返しを文の側に置けるが、隔離やスキーマまでファイルへ流れ、検証できなくなる。
- **JSON / YAML でプロンプトを持つ**: 長い文を書く形式として読みにくい。Markdown の節は人が読み書きしやすい。
- **文の改善と同時に移す**: 何が挙動を変えたか追えなくなる。移行は等価変換だけにし、改善は実測とセットで別に行う。
- **DB に持って画面で編集する**: 版管理・差分・レビューが git でできなくなる。ファイルなら PR で文の変更を追える。

## 結果・影響

- `prompts/` が製品の一部になる。文の変更は PR で差分として見える。
- 各 use case が `PromptCatalogPort` を受け取る（コンストラクタの引数が増える）。テストは同梱の実ファイルで動く。
- 節の名前とコードの `PromptSpec` は対で守る。宣言されていないファイル・節はテストで落とす（死んだ文を残さない）。
- 非スコープ: 文の改善、プロンプトの画面編集、多言語化。
