# 18. クイックスタート

はじめて agentblume を動かす人向けの手順書。**インストール → 起動 → モデル設定 → サンプルで動かす → 自分のデータで作る**までを、画面の表示どおりに進める。

所要時間はおよそ30分（モデルのダウンロード時間を除く）。プログラミングの知識は要らないが、**PowerShellでコマンドを1〜2行打つ場面がある**。

> 画面の表記は日本語と英語を切り替えられる。本書は**日本語表示**を前提に書く。切り替えは「設定」画面の「表示言語」で行う。

---

## 0. 前提

| | 要件 | 確認方法・入手先 |
|---|---|---|
| **Node.js** | **22.9.0 以上** | PowerShellで `node -v`。無い／古い場合は [nodejs.org](https://nodejs.org/) から LTS を入れる |
| **PowerShell 7+** (`pwsh`) | 開発用の起動スクリプトを使う場合 | `pwsh -v`。本番起動（§2の方法B）だけなら不要 |
| **LLMの接続先** | エージェントを実際に会話させる場合 | 下の「モデルの選択肢」を参照 |

**モデルの選択肢**は2つある。どちらか一方でよい。

- **A. ローカルで動かす（LM Studio など）** — 費用がかからず、データが外部に出ない。[LM Studio](https://lmstudio.ai/) を入れ、**Tool Calling（関数呼び出し）に対応したモデル**をロードして、OpenAI互換サーバーを起動しておく（既定の接続先は `http://127.0.0.1:1234/v1`）。
- **B. クラウドのAPIを使う（OpenAI など）** — APIキーが必要。利用料がかかる。

> モデルが無くても、UI・データソース登録・ツールビルダーのプレビューは動く。**会話（チャット）とFactoryと評価だけ**がモデルを必要とする。

---

## 1. インストール

リポジトリを取得したフォルダで、PowerShellを開いて実行する。

```powershell
npm install
```

設定を書き換えたい場合だけ、環境変数ファイルを用意する（無くてもよい）。

```powershell
copy .env.example .env
```

読み込まれる環境変数の全量と既定値は [.env.example](../.env.example) にある。

---

## 2. 起動する

### 方法A: 開発用に起動する（変更しながら試す人向け）

```powershell
.\scripts\start-dev.ps1
```

APIが `3030`、UIが `5173` で起動する。ブラウザで **`http://127.0.0.1:5173`** を開く。

止めるときは起動したウィンドウで `Ctrl+C`。異常終了してポートが残った場合は `.\scripts\start-dev.ps1 -Stop` で掃除できる。

ポートが使用中のときは自動で他プロセスを止めずにエラーになる。別ポートで起動する場合:

```powershell
.\scripts\start-dev.ps1 -ApiPort 3031 -UiPort 5174
```

### 方法B: ビルドして起動する（普通に使う人向け）

```powershell
npm run build
npm start
```

ブラウザで **`http://127.0.0.1:3030`** を開く。UIとAPIが同じポートから配信されるので、これだけで使える。

> **認証機能はまだ無い。** `AGENTCONTEXT_HOST=0.0.0.0` にして社内LANや公開網へ出さないこと。

### 起動できたら

左側にナビゲーションが出る。上から「チャット」、そして3つのグループが並ぶ。

| グループ | 画面 |
|---|---|
| **作る** | データソース / ツール / スキル / エージェント / マルチエージェント / 自動生成 (Factory) |
| **確かめる** | 動作確認 / 検証 |
| **運用** | 記憶 / MCP / ステータス / 設定 |

各画面には**ヘルプ**がある。左ナビ下部の「**? ヘルプ**」を押すと、いま開いている画面の説明が出る。

---

## 3. モデルを設定する

チャットを使うには、先にモデルを保存する。**これをやらないとエージェントは応答できない。**

1. 左ナビの「**設定**」を選ぶ。
2. ページ下部の「**モデルプロバイダ**」まで進む。「**メインモデル**」と「**評価モデル**」の2つのスロットがある。
   - **メインモデル** (`main`) … エージェントの実行に使う。**まずこれを設定する。**
   - **評価モデル** (`judge`) … 検証画面のLLM採点に使う。後回しでよい。
3. 「**メインモデル**」の「**プロバイダ**」を選ぶ。選べるのは次の主要プロバイダである。

| プロバイダ | 入力するもの |
|---|---|
| OpenAI / Anthropic / Google | モデルID + APIキー |
| Microsoft Azure AI Foundry | ベースURL（`https://<resource>.services.ai.azure.com/openai/v1`）+ デプロイ名 + APIキー |
| AWS Bedrock | ベースURL（`https://bedrock-runtime.<region>.amazonaws.com/openai/v1`）+ モデルID + APIキー |
| Google Cloud Vertex AI | ベースURL（プロジェクト・リージョンを含む）+ モデルID + アクセストークン |
| OpenAI互換エンドポイント（LM Studio・vLLM など） | ベースURL + モデルID（APIキーは不要なことが多い） |

> **モデル名のプルダウンは無い。** モデルは提供元で頻繁に入れ替わり、Azure・Bedrock・Vertex では**自分でデプロイ・有効化したモデルしか使えない**ため、こちらで固定の一覧を出しても正しくならない。「**モデルID / デプロイ名**」欄に、提供元のコンソールに表示されているIDをそのまま入力する（欄の下のリンクから提供元のモデル一覧を開ける）。

### ローカル（LM Studio など）の場合

1. プロバイダで「**OpenAI互換エンドポイント（LM Studio・vLLM など）**」を選ぶ。「**ベースURL**」には既定値 `http://127.0.0.1:1234/v1` が入っている。
2. 「**モデル一覧を取得**」を押す。LM Studio が起動していれば、ロード済みモデルが「モデルID」欄の入力候補になる（1件目は自動で入る）。
   - 取得できない場合もモデルIDを直接入力すればよい。
3. 「**APIキー**」は通常は空でよい（LM Studioは不要）。
4. 「**保存**」を押す。
5. 「**テスト**」を押して `ok (…ms): …` と出れば接続できている。

### クラウドAPI（OpenAI・Azure AI Foundry など）の場合

1. 「**プロバイダ**」のプルダウンから使うサービスを選ぶ（`OpenAI · OPENAI_API_KEY` のように、そのプロバイダが読む環境変数名も併記される）。
2. Azure / Bedrock / Vertex を選んだ場合は「**ベースURL**」に雛形が入るので、`<resource>` `<region>` `<project>` の部分を自分の値に置き換える（置き換えるまで保存ボタンは押せない）。
3. 「**モデルID / デプロイ名**」に、提供元で使えるモデル（Azure ならデプロイ名）を入力する。
4. 「**APIキー**」に発行済みのキーを貼る。
5. 「**保存**」を押す。保存に成功するとAPIキー欄はクリアされる。
6. 「**テスト**」で接続を確認する。

> 上の一覧に無いサービス（OpenRouter・Groq など）も、OpenAI互換であれば「**OpenAI互換エンドポイント**」にベースURLとキーを入れれば使える。

> **APIキーの扱い**: キーは暗号化して保存され、**ブラウザへ戻されることはない**（一度保存すると末尾4文字しか表示されない）。暗号鍵は `~/.agentblume/secret.key` に置かれる。DBファイルをバックアップ・共有するときに**鍵ファイルを一緒に運ばないこと**。
>
> 環境変数（`LM_STUDIO_BASE_URL` など）で既定を与えることもできる。スロットを未設定のままにすると環境変数の既定が使われ、画面には「環境変数の既定（LM Studio）を使用中」と表示される。

## 4. サンプルを読み込んで動かす

自分のデータを用意する前に、動く状態を1度見ておくと理解が早い。

1. 左ナビの「**チャット**」を開く。データが何も無い状態では「**AgentBlumeへようこそ**」というカードが出る。
2. 「**サンプルを読み込んで試す**」を押す。

> カードが出ない場合（既にデータがある場合など）は、「**データソース**」画面の「**サンプルを読み込む**」からでも同じことができる。

投入されるのは次の一式。同じIDが既にあるときは作り直さない（何度押しても安全）。

| 種別 | 名前 | 用途 |
|---|---|---|
| データソース | `sample-products.csv` | 商品3件 |
| データソース | `sample-customers.json` | 顧客2件 |
| データソース | `sample-monthly-sales.csv` | 月次売上6行。Factoryの練習に使う |
| ツール | `Sample Product Catalog` | 商品カタログをエージェントへ返す |
| スキル | `Sample Product Analysis` | カタログに基づく回答規則 |
| Wiki | `Sample Product Operations` | 在庫・価格・カテゴリの判断規則 |
| エージェント | `Sample Product Assistant` | 上の3つを割り当てたデモ用エージェント |

読み込みが終わると「**サンプルのエージェントと話す**」ボタンが出る。押すとチャットへ移動する。

---

## 5. 最初のエージェントと会話する

1. 左ナビの「**チャット**」を開く。
2. 入力欄の下にある「**チャット対象エージェント**」のプルダウンで `Sample Product Assistant · 1.0.0` を選ぶ。
3. 質問を入力して `Enter` で送信する（改行は `Shift+Enter`）。

試しやすい質問:

```text
在庫のあるelectronics商品を価格付きで比較して。
```

実行中は入力欄の右のボタンが**停止ボタン**に変わる。時間がかかりすぎたら押して中断できる（入力内容は欄に戻る）。10秒・30秒・2分の節目で状況の説明が表示される。

応答の下には、どのツールを何回呼んだか・トークン数・所要時間が出る。**何が起きたかを詳しく見たい**ときは、左ナビの「**動作確認**」画面で同じ質問を投げると、トレース（モデル要求 → ツール呼び出し → ツール結果 → 最終応答）を1件ずつ確認できる。

> 画像を添付する場合は、入力欄の左のクリップ「画像を添付」から選ぶ。PNG・JPEG・WebP・GIFを最大2枚、各3 MiBまで。画像入力に対応したモデルが必要で、画像だけでは送信できない（指示文も入れる）。

## 6. 自分のデータでツールを作る

ここからが本番。**「データを登録する → ツールにする → エージェントに持たせる」**の3ステップ。

### 6.1 データを登録する

1. 左ナビの「**データソース**」を開く。
2. 「**ファイルをアップロード**」で、手元の **CSV または JSON** を選ぶ（1ファイル最大5 MB）。
3. 「**ソース名**」は空でよい（ファイル名が使われる）。分かりやすい名前を付けてもよい。
4. 「**アップロード**」を押す。「登録済みソース」に現れれば成功。

> データベース（PostgreSQL）から読むこともできるが、**接続情報はブラウザに入力しない**。サーバー側の環境変数 `AGENTCONTEXT_DB_CONNECTIONS` で構成済みの接続IDだけがプルダウンに現れる。設定方法は [.env.example](../.env.example) を参照。

### 6.2 ツールを作る

ツールは「入力 → 変換 → 出力」の流れ図で、**LLMを使わずに決まった手順でデータを加工する部品**である。エージェントはこれを呼び出して、確実な数字や一覧を手に入れる。

1. 左ナビの「**ツール**」を開く。「ツール一覧」が出る。
2. 「**新規作成**」を押す。
   - 時系列の取り出し・ランキング・前期比・2 つのデータの比のような**よくある形**は、隣の「**テンプレートから作成**」のほうが早い。テンプレートを選び、データソースと列を選ぶだけでキャンバスができあがる（[docs/06 §3.16](./06-etl-tool-builder.md#316-テンプレートから作成外部ファイル)）。以降の手順は同じで、所有者を入れて保存する。
   - どちらでもない・組んだ後に手直ししたいときは、ヘッダーの「**設計アシスタント**」を押す。開いたチャット欄に「都道府県別の人口を年次に絞って多い順に10件返して」のように日本語で書くと、話しながらキャンバスにノードが増えていく（保存はされないので、気に入らなければ「この変更を取り消す」で戻せる）。ローカルLLM未設定時はボタンは押せるが入力欄が無効になり、設定箇所が案内される（[docs/06 §3.17](./06-etl-tool-builder.md#317-設計アシスタント文章で指示するとノードが増える)）。
3. 上部の「**メタデータ**」を開き、少なくとも次を埋める。
   - **内部ID** … 英数字とハイフン。例 `monthly-sales`
   - **作業名** / **公開名** … 公開名はエージェントが呼ぶときの名前になる。例 `monthly_sales`
   - **所有者**
4. 左の「**ノード**」から、「**入力**」の「**CSV入力**」（JSONなら「**JSON入力**」）を押してキャンバスに置く。
5. そのノードを選び、右の「**インスペクター**」で「**登録済みデータソース**」から §6.1 で登録したファイルを選ぶ。
6. 必要なら「**変換**」から加工ノードを足してつなぐ。よく使うもの:
   - **列選択** … 必要な列だけ残す
   - **行フィルター** … 条件に合う行だけ残す
   - **並べ替え** + **行数制限** … 上位N件を作る
   - **グループ集計** … 件数・合計などを集計する
   - **関数電卓** … 数式で新しい列を計算する（税込金額 = `[金額] * 1.1` など。電卓風のボタンで組める。式のすぐ下の「✨ AIに式を書かせる」キーで、やりたいことを日本語で書いて式を作らせることもできる。ローカルLLM未設定時はキーが無効化され、設定箇所が案内される）
7. 「**出力**」から「**エージェント出力**」を置き、最後のノードとつなぐ。**出力ノードは終端に1つだけ**置ける。
8. 下部の「**プレビュー**」で実際の行が出ることを確認する。ここはモデルを使わないので、LM Studio が止まっていても確認できる。
9. 「**バージョンを保存**」を押す。

> 保存できないときは、ボタンの近くに「〜が未入力です」と不足項目が表示される。

### 6.3 エージェントに持たせる

1. 左ナビの「**エージェント**」を開き、「**新規作成**」を押す。
2. 「**定義**」に内部ID・表示名・公開名・所有者を入れる。
3. 「**ツール**」で §6.2 のツールにチェックを入れる。
4. 「**草案を生成**」を押すと、選んだツール・スキルの情報からシステムプロンプトの下書きが作られる。そのまま編集してよい。
5. 「**バージョンを保存**」を押す。
6. 「**保存済みエージェントのプレビュー**」で「**保存済みエージェントを実行**」を押すか、チャット画面へ移って会話する。

> **実行オプション**（ヘッダーのボタン）で、そのエージェントだけの実行時機能をオンにできる — ファイルメモリ、TODOリスト、コンパクション、Web検索、ツール承認、ツール自動実行。既定では「ツール自動実行」だけがオン。
> これは**マルチエージェント画面とは別の機能**なので混同しないこと。

---

### 6.4 ツールを単体で検証する（ツール検証）

エージェントに持たせる前に、ツールが期待どおりの表を返すかを「確かめる → **ツール検証**」で確認できる。

1. 上部の「ツール」で保存したツールを選ぶ（版は「最新」のままでよい）。引数の欄はツールの入力スキーマから自動で出る。
2. 引数を入れて「**実行**」。出力の表と行数、ノード別の行数が出る。エラーになったら、表示されるボタン「ツール「…」のノード「…」を開いて直す」で該当ノードへ戻れる。
3. 必要なら「期待」に行数・存在すべき列・セル条件・所要時間上限を入れて、もう一度「実行」すると合格 / 不合格が出る。「AI判定」ノードを含むツールなら、行を特定して「この行は no と判定されたか」まで期待に書ける。
4. 「ケース名」を入れて「**ケースとして保存**」。以後はツールやデータを変えた後に左の一覧から「実行」、または「**すべて実行**」でまとめて退行を確認できる。

ケースを自分で考えるのが面倒なら、「新規」の隣の「**LLMでケースを提案**」を使う。設定中のモデルがツール定義を読んで 正常 / 境界 / 異常 のケース案を作るので、カードの「**実行して確認**」で合否を見て、残したいものを「**保存**」する（「エディタに読み込む」で直してから保存もできる）。異常系の案は「失敗が期待値」になっていて、実行が失敗すれば合格になる。ボタンが無効なときは設定中のモデルが構造化出力に対応していないので、設定画面で対応モデルを選ぶ。

### 6.5 LLM採点を調整する（検証 → データセット / 実験）

エージェントの回答を評価モデル（`judge`）に採点させるときの設定。基準ごとに判定し、合成スコア = Σ 重み×水準 / Σ 重み（判定不能の基準は除外）になる。

- **先に評価モデル（`judge`）を設定する** … ルーブリックを含む評価プロファイルで実験を開始するには、設定画面の judge スロットにモデルが要る。未設定だと実験タブの「実験を開始」の上に「判定モデルが未設定です」の注意が出て、「設定で判定モデルを設定」ボタンで設定画面の該当カードへ飛べる（サーバーも `JUDGE_MODEL_NOT_CONFIGURED` で起票を拒否する）。
- **Judge Rubric の「判定者に見せる実行履歴」** … 任意（あれば見せる・既定）／必須（履歴の無い事例は判定失敗 `JUDGE_INPUT`）／禁止（回答だけで判定）。**「必須」はターン事例だけで使える**。シナリオ事例（疑似ユーザー会話）はツール呼び出しの軌跡を残さないため、シナリオ事例を含むデータセットで起票すると `JUDGE_TRACE_UNAVAILABLE` で拒否され、「ルーブリックを開く」ボタンからそのルーブリックの編集へ移れる。ポリシーを「任意」にするか、ターン事例だけのデータセットを使う。
- **基準の「二値にする」** … 水準を 0 = 未達 / 1 = 達成 に置き換える。順序尺度より判定の一致率が高いので、迷ったら二値にする。
- **実験の「判定サンプル数」**（1〜5） … 2 以上で同じ事例を複数回判定し、中央値を採用する。差が大きい事例は結果に「ばらつき大」の印が付く。
- 結果の各判定には基準別のスコア（「判定不能」は理由をホバーで表示）、判定に使ったトークン数、プロンプトの指紋が出る。失敗したときは原因と次の一手（ポリシーの変更・基準の具体化・判定モデルの変更）が表示される。
- 品質ゲートの比較表には基準別の指標が `指標 › 基準` として合成指標の下に並び、ゲートの指標としても指定できる（例 `judge:accuracy`）。

## 7. 伝票を仕訳にする

レシート・請求書・銀行/カード明細から仕訳を起こして会計ソフト用の CSV を出す。左ナビ「作る → **業務テンプレート**」を開き、一覧から **仕訳** を選ぶ（`#/journal` への直リンクもそのまま使える）。

> 業務テンプレートは**実験的な機能**なので、初期状態では左ナビに出ない。先に左ナビ「運用 → **設定**」の「実験的な機能」で **実験的な機能を表示する** をオンにする（このブラウザに保存される）。
**科目と税区分は自分で決める**（初期セットは入っているが、名前も区分も自由に変えられる）。

試すためのサンプル帳票一式（すべて架空）が [`samples/journal/`](../samples/journal/README.md) にある。

1. **CSV を取り込む** … 「**取込**」タブ →「CSV（銀行 / カード）」でファイルを選ぶ。ヘッダー行からプリセットを自動判定し（判定できないときは手動で選ぶ）、先頭 5 行のプレビューが出る。Shift-JIS の CSV もそのまま読める。「取り込む」を押すと 1 行 = 1 帳票になり、取り込めなかった行は理由付きで表に出る。
   - 試すなら `samples/journal/bank-generic.csv`（汎用・9 行）。Shift-JIS は `samples/journal/bank-mufg.sjis.csv`、カード明細は `samples/journal/card-rakuten.csv`。
   - CSV 以外は同じタブの「事実フォーム」（手入力）、「JSON を貼り付け」（`samples/journal/invoice-qualified.json` などの `facts` をそのまま貼れる）から入れる。画像 / PDF / テキストは次の手順の AI 読取が使える。
2. **AI で読み取る（画像 / PDF / テキスト）** … 「**取込**」タブ →「画像 / PDF」でレシートの写真や PDF を選ぶ（ドラッグ＆ドロップ可、1 回の読み取りにつき 4 枚まで）。PDF は**ブラウザ側**でページ画像にしてから送るので、PDF そのものはサーバーに渡らない。「AI で読み取る」を押すと事実フォームに読み取り結果が入るので、**内容を確かめてから保存**する。信頼度の低い項目には「要確認」の印が付き、マウスを載せると根拠にした原文の断片が出る。読み取り時の注意（税率別合計と総額が合わない、登録番号の桁数が違う等）は一覧で表示される。
   - 試すなら `samples/journal/rendered/invoice-qualified.png`（A4 の適格請求書）と `samples/journal/rendered/receipt-simplified.png`。メール本文は `samples/journal/mail-invoice-notice.txt` を「テキスト」に貼って同じボタンを押す。
   - **時間の目安**: ローカルモデル（LM Studio）では 12B 級で 1 枚あたり十数秒、より大きいモデルでは同じレシートに数分かかることもある。**大きいモデルほど正確だが遅い**というトレードオフなので、枚数が多いときは小さいモデルにするとよい。経過秒数と「中断」ボタンが出るので、待てないときは中断してよい（読み取りも保存も行われない）。
   - 画像は長辺 2000px に縮めて送る（元より大きくは引き伸ばさない）。**長辺 1200px を下回ると読み間違いが増える**（実測で登録番号の桁数と 8% 対象額を誤読した）ので、注意が出たら帳票が画面いっぱいになるように撮り直す。サムネイルの下に実寸が出る。
3. **判定する** … 「**判定**」タブ →「未判定を判定」。自分のルールに 1 件だけ当たれば仕訳ドラフトができて「確定」、当たらなければ「未確定」になる。見積書・納品書（`quotation.json` / `delivery-note.json`）は仕訳の対象外なので「対象外」になる。
4. **未確定の理由を読んでルールを作る** … 帳票を選ぶと「**原因 → 次の一手 → 直す場所へのボタン**」が出る。ボタンを押すと直す場所（ルール編集・科目マスタ・帳票の項目）へそのまま移れる。

   | 未確定の理由 | 意味 | 次の一手 |
   |---|---|---|
   | 該当ルール無し | 一致する有効なルールが無い | 「ルールを作る」（摘要から条件を事前入力してくれる） |
   | 複数ルールが同点 | 同じ強さのルールが 2 つ以上当たった | 採用したいルールの優先度を上げるか、条件を具体的にする |
   | 必要項目の不足 | ルールが要求する項目が帳票に無い | 「項目を編集」で補ってから再判定する |
   | 追加質問あり | ルールの確認質問に該当した（例: 10 万円以上の PC） | その場で回答する。回答は帳票に保存され再判定される |
   | 推測ルールのみ一致 | 当たったのが推測モードのルールだけ | 信頼できるなら自動モードに切り替える |
   | 科目がマスタに無い | ルールの科目が消えた・無効になっている | 「科目マスタを開く」で有効化するか作り直す |
   | 貸借不一致 | ルールの行の借方合計と貸方合計が違う | 片側の金額指定を「残額」にする |

   科目を増やす・並べ替える・弥生 / freee / マネーフォワードの税区分名を対応づけるのは「**科目**」タブ（CSV の出し入れと「標準に戻す」もここ）。
5. **ヒアリングでルールを作らせる**（main モデルが構造化出力に対応しているとき） … 未確定の帳票で「**ヒアリングを開始**」。モデルが用途・相手先・資産かどうかなどを 1〜3 問聞いてくるので答えると、**ルール案と仕訳のプレビュー**が出る（科目は自分のマスタの名前で表示される）。新しい科目や税区分が要るときは「これらを科目マスタに登録します」に候補が並ぶが、**既定ではすべて未チェック**で、チェックしたものだけが登録される。案を直したいときは「ルールを編集してから登録」を押すと、その内容が入った状態でルール編集フォームが開く。登録すると仕訳ができ、「ヒアリングをやめる」を押せば帳票は未確定に戻る。提案が科目と噛み合わなかったときは、原因と「手でルールを作る」ボタンが出る。
6. **CSV に出す** … 「**出力**」タブで状態と期間を絞って「出力する」。汎用 CSV（UTF-8 BOM・CRLF・1 行 = 1 仕訳行）がダウンロードされる。「出力した仕訳を『出力済』にする」を選べば二重出力を防げる。手入力の仕訳もこのタブで足せる（貸借が合わないと保存できない）。

詳しい仕様は [20-journal.md](./20-journal.md)。

## 9. 作ったデータはどこにあるか

作成したツール・スキル・エージェント・Wiki・実行履歴・モデル設定は SQLite に保存される。

- 既定の保存先は **`~/.agentblume/agentblume.db`**（起動時のログに実際のパスが出る）。
- 場所を変えるには `AGENTCONTEXT_DB_PATH` を設定する。
- **`AGENTCONTEXT_DB_PATH=:memory:` を指定したときだけ、プロセスを止めると全データが消える**（使い捨て検証用）。
- 表やグラフの実体は `<DBファイル>.session-artifacts/` に置かれる。**DBファイルとこのフォルダは常に一緒に扱う。**

バックアップは「**ステータス**」画面の「バックアップと掃除」、またはコマンドで取れる。

```powershell
npm run backup            # 取得
npm run backup -- --list  # 一覧
```

**動作中のDBファイルを直接コピーしてはいけない**（WALのため整合しないコピーになる）。詳細は[運用 runbook](./17-operations-runbook.md)を参照。
