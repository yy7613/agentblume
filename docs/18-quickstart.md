# 18. クイックスタート

はじめて agentblume を動かす人向けの手順書。**インストール → 起動 → モデル設定 → サンプルで動かす → 自分のデータで作る**までを、画面の表示どおりに進める。

所要時間はおよそ30分（モデルのダウンロード時間を除く）。プログラミングの知識は要らないが、**PowerShellでコマンドを1〜2行打つ場面がある**。

> 画面の表記は日本語と英語を切り替えられる。本書は**日本語表示**を前提に書く。切り替えは「設定」画面の「表示言語」で行う。

---

## 0. 前提

| | 要件 | 確認方法・入手先 |
|---|---|---|
| **Node.js** | **22.9.0 以上** | PowerShellで `node -v`。無い／古い場合は [nodejs.org](https://nodejs.org/) から LTS を入れる |
| **PowerShell 7+** (`pwsh`) | 開発用の起動スクリプトを使う場合 | `pwsh -v`。本番起動（§2の方法B）だけなら不要 |
| **LLMの接続先** | エージェントを実際に会話させる場合 | 下の「モデルの選択肢」を参照 |

**モデルの選択肢**は2つある。どちらか一方でよい。

- **A. ローカルで動かす（LM Studio など）** — 費用がかからず、データが外部に出ない。[LM Studio](https://lmstudio.ai/) を入れ、**Tool Calling（関数呼び出し）に対応したモデル**をロードして、OpenAI互換サーバーを起動しておく（既定の接続先は `http://127.0.0.1:1234/v1`）。
- **B. クラウドのAPIを使う（OpenAI など）** — APIキーが必要。利用料がかかる。

> モデルが無くても、UI・データソース登録・ツールビルダーのプレビューは動く。**会話（チャット）とFactoryと評価だけ**がモデルを必要とする。

---

## 1. インストール

リポジトリを取得したフォルダで、PowerShellを開いて実行する。

```powershell
npm install
```

設定を書き換えたい場合だけ、環境変数ファイルを用意する（無くてもよい）。

```powershell
copy .env.example .env
```

読み込まれる環境変数の全量と既定値は [.env.example](../.env.example) にある。

---

## 2. 起動する

### 方法A: 開発用に起動する（変更しながら試す人向け）

```powershell
.\scripts\start-dev.ps1
```

APIが `3030`、UIが `5173` で起動する。ブラウザで **`http://127.0.0.1:5173`** を開く。

止めるときは起動したウィンドウで `Ctrl+C`。異常終了してポートが残った場合は `.\scripts\start-dev.ps1 -Stop` で掃除できる。

ポートが使用中のときは自動で他プロセスを止めずにエラーになる。別ポートで起動する場合:

```powershell
.\scripts\start-dev.ps1 -ApiPort 3031 -UiPort 5174
```

### 方法B: ビルドして起動する（普通に使う人向け）

```powershell
npm run build
npm start
```

ブラウザで **`http://127.0.0.1:3030`** を開く。UIとAPIが同じポートから配信されるので、これだけで使える。

> **認証機能はまだ無い。** `AGENTCONTEXT_HOST=0.0.0.0` にして社内LANや公開網へ出さないこと。

### 起動できたら

左側にナビゲーションが出る。上から「チャット」、そして3つのグループが並ぶ。

| グループ | 画面 |
|---|---|
| **作る** | データソース / ツール / スキル / エージェント / マルチエージェント / 自動生成 (Factory) |
| **確かめる** | 動作確認 / 検証 |
| **運用** | 記憶 / MCP / ステータス / 設定 |

各画面には**ヘルプ**がある。左ナビ下部の「**? ヘルプ**」を押すと、いま開いている画面の説明が出る。

---

## 3. モデルを設定する

チャットを使うには、先にモデルを保存する。**これをやらないとエージェントは応答できない。**

1. 左ナビの「**設定**」を選ぶ。
2. ページ下部の「**モデルプロバイダ**」まで進む。「**メインモデル**」と「**評価モデル**」の2つのスロットがある。
   - **メインモデル** (`main`) … エージェントの実行に使う。**まずこれを設定する。**
   - **評価モデル** (`judge`) … 検証画面のLLM採点に使う。後回しでよい。
3. 「**メインモデル**」の「**ソース**」を選ぶ。

### ローカル（LM Studio など）の場合

1. ソースで「**OpenAI互換エンドポイント**」を選ぶ。
2. 「**ベースURL**」に LM Studio のアドレスを入れる（既定は `http://127.0.0.1:1234/v1`）。
3. 「**モデル一覧を取得**」を押す。LM Studio が起動していれば、ロード済みモデルが「モデル」のプルダウンに並ぶ。
   - 一覧が取れない場合は「**手入力**」を選んで、「**モデル名**」にモデルIDを直接入力する。
4. 「**APIキー**」は通常は空でよい（LM Studioは不要）。
5. 「**保存**」を押す。
6. 「**テスト**」を押して `ok (…ms): …` と出れば接続できている。

### クラウドAPI（OpenAI など）の場合

1. ソースで「**プロバイダレジストリ**」を選ぶ。
2. 「**プロバイダ**」のプルダウンから使うサービスを選ぶ（`openai · OPENAI_API_KEY` のように、そのプロバイダが読む環境変数名も併記される）。
3. 「**モデル**」のプルダウンからモデルを選ぶ。一覧に無ければ「**手入力**」でモデル名を直接入れる。
4. 「**APIキー**」に発行済みのキーを貼る。
5. 「**保存**」を押す。保存に成功するとAPIキー欄はクリアされる。
6. 「**テスト**」で接続を確認する。

> **APIキーの扱い**: キーは暗号化して保存され、**ブラウザへ戻されることはない**（一度保存すると末尾4文字しか表示されない）。暗号鍵は `~/.agentblume/secret.key` に置かれる。DBファイルをバックアップ・共有するときに**鍵ファイルを一緒に運ばないこと**。
>
> 環境変数（`LM_STUDIO_BASE_URL` など）で既定を与えることもできる。スロットを未設定のままにすると環境変数の既定が使われ、画面には「環境変数の既定（LM Studio）を使用中」と表示される。

## 4. サンプルを読み込んで動かす

自分のデータを用意する前に、動く状態を1度見ておくと理解が早い。

1. 左ナビの「**チャット**」を開く。データが何も無い状態では「**AgentBlumeへようこそ**」というカードが出る。
2. 「**サンプルを読み込んで試す**」を押す。

> カードが出ない場合（既にデータがある場合など）は、「**データソース**」画面の「**サンプルを読み込む**」からでも同じことができる。

投入されるのは次の一式。同じIDが既にあるときは作り直さない（何度押しても安全）。

| 種別 | 名前 | 用途 |
|---|---|---|
| データソース | `sample-products.csv` | 商品3件 |
| データソース | `sample-customers.json` | 顧客2件 |
| データソース | `sample-monthly-sales.csv` | 月次売上6行。Factoryの練習に使う |
| ツール | `Sample Product Catalog` | 商品カタログをエージェントへ返す |
| スキル | `Sample Product Analysis` | カタログに基づく回答規則 |
| Wiki | `Sample Product Operations` | 在庫・価格・カテゴリの判断規則 |
| エージェント | `Sample Product Assistant` | 上の3つを割り当てたデモ用エージェント |

読み込みが終わると「**サンプルのエージェントと話す**」ボタンが出る。押すとチャットへ移動する。

---

## 5. 最初のエージェントと会話する

1. 左ナビの「**チャット**」を開く。
2. 入力欄の下にある「**チャット対象エージェント**」のプルダウンで `Sample Product Assistant · 1.0.0` を選ぶ。
3. 質問を入力して `Enter` で送信する（改行は `Shift+Enter`）。

試しやすい質問:

```text
在庫のあるelectronics商品を価格付きで比較して。
```

実行中は入力欄の右のボタンが**停止ボタン**に変わる。時間がかかりすぎたら押して中断できる（入力内容は欄に戻る）。10秒・30秒・2分の節目で状況の説明が表示される。

応答の下には、どのツールを何回呼んだか・トークン数・所要時間が出る。**何が起きたかを詳しく見たい**ときは、左ナビの「**動作確認**」画面で同じ質問を投げると、トレース（モデル要求 → ツール呼び出し → ツール結果 → 最終応答）を1件ずつ確認できる。

> 画像を添付する場合は、入力欄の左のクリップ「画像を添付」から選ぶ。PNG・JPEG・WebP・GIFを最大2枚、各3 MiBまで。画像入力に対応したモデルが必要で、画像だけでは送信できない（指示文も入れる）。

## 6. 自分のデータでツールを作る

ここからが本番。**「データを登録する → ツールにする → エージェントに持たせる」**の3ステップ。

### 6.1 データを登録する

1. 左ナビの「**データソース**」を開く。
2. 「**ファイルをアップロード**」で、手元の **CSV または JSON** を選ぶ（1ファイル最大5 MB）。
3. 「**ソース名**」は空でよい（ファイル名が使われる）。分かりやすい名前を付けてもよい。
4. 「**アップロード**」を押す。「登録済みソース」に現れれば成功。

> データベース（PostgreSQL）から読むこともできるが、**接続情報はブラウザに入力しない**。サーバー側の環境変数 `AGENTCONTEXT_DB_CONNECTIONS` で構成済みの接続IDだけがプルダウンに現れる。設定方法は [.env.example](../.env.example) を参照。

### 6.2 ツールを作る

ツールは「入力 → 変換 → 出力」の流れ図で、**LLMを使わずに決まった手順でデータを加工する部品**である。エージェントはこれを呼び出して、確実な数字や一覧を手に入れる。

1. 左ナビの「**ツール**」を開く。「ツール一覧」が出る。
2. 「**新規作成**」を押す。
3. 上部の「**メタデータ**」を開き、少なくとも次を埋める。
   - **内部ID** … 英数字とハイフン。例 `monthly-sales`
   - **作業名** / **公開名** … 公開名はエージェントが呼ぶときの名前になる。例 `monthly_sales`
   - **所有者**
4. 左の「**ノード**」から、「**入力**」の「**CSV入力**」（JSONなら「**JSON入力**」）を押してキャンバスに置く。
5. そのノードを選び、右の「**インスペクター**」で「**登録済みデータソース**」から §6.1 で登録したファイルを選ぶ。
6. 必要なら「**変換**」から加工ノードを足してつなぐ。よく使うもの:
   - **列選択** … 必要な列だけ残す
   - **行フィルター** … 条件に合う行だけ残す
   - **並べ替え** + **行数制限** … 上位N件を作る
   - **グループ集計** … 件数・合計などを集計する
7. 「**出力**」から「**エージェント出力**」を置き、最後のノードとつなぐ。**出力ノードは終端に1つだけ**置ける。
8. 下部の「**プレビュー**」で実際の行が出ることを確認する。ここはモデルを使わないので、LM Studio が止まっていても確認できる。
9. 「**バージョンを保存**」を押す。

> 保存できないときは、ボタンの近くに「〜が未入力です」と不足項目が表示される。

### 6.3 エージェントに持たせる

1. 左ナビの「**エージェント**」を開き、「**新規作成**」を押す。
2. 「**定義**」に内部ID・表示名・公開名・所有者を入れる。
3. 「**ツール**」で §6.2 のツールにチェックを入れる。
4. 「**草案を生成**」を押すと、選んだツール・スキルの情報からシステムプロンプトの下書きが作られる。そのまま編集してよい。
5. 「**バージョンを保存**」を押す。
6. 「**保存済みエージェントのプレビュー**」で「**保存済みエージェントを実行**」を押すか、チャット画面へ移って会話する。

> **実行オプション**（ヘッダーのボタン）で、そのエージェントだけの実行時機能をオンにできる — ファイルメモリ、TODOリスト、コンパクション、Web検索、ツール承認、ツール自動実行。既定では「ツール自動実行」だけがオン。
> これは**マルチエージェント画面とは別の機能**なので混同しないこと。

## 7. 迷ったときの近道

| やりたいこと | 行き先 |
|---|---|
| 何から書けばいいか分からない | 「**自動生成 (Factory)**」画面。やりたいことを文章で書き、データソースを選ぶと、ツール・スキル・エージェント一式を自動生成して自動改善する（[docs/16](./16-agent-factory.md)） |

## 8. 作ったデータはどこにあるか

作成したツール・スキル・エージェント・Wiki・実行履歴・モデル設定は SQLite に保存される。

- 既定の保存先は **`~/.agentblume/agentblume.db`**（起動時のログに実際のパスが出る）。
- 場所を変えるには `AGENTCONTEXT_DB_PATH` を設定する。
- **`AGENTCONTEXT_DB_PATH=:memory:` を指定したときだけ、プロセスを止めると全データが消える**（使い捨て検証用）。
- 表やグラフの実体は `<DBファイル>.session-artifacts/` に置かれる。**DBファイルとこのフォルダは常に一緒に扱う。**

バックアップは「**ステータス**」画面の「バックアップと掃除」、またはコマンドで取れる。

```powershell
npm run backup            # 取得
npm run backup -- --list  # 一覧
```

**動作中のDBファイルを直接コピーしてはいけない**（WALのため整合しないコピーになる）。詳細は[運用 runbook](./17-operations-runbook.md)を参照。
