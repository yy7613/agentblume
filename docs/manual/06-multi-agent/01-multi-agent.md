# マルチエージェント

この節では、保存済みの複数エージェントを役割（slot）へ割り当て、1つの「マルチエージェント」として保存し、チャットの実行対象として使うまでを説明する。

## マルチエージェントとは

マルチエージェントは、保存済みエージェントの**バージョンを固定して**役割へ割り当て、6種類のオーケストレーション方式（パターン）のどれかで動かす機能である。利用者から見えるのは常に1つの実行対象で、会話中に複数のエージェントが動いていることはチャットの中間表示（後述）でしか意識しない。

> **似た機能との違い**: エージェント編集画面の「[サブエージェント](../04-agents/03-attach-tools-and-more.md#サブエージェント)」は、1つのエージェントが必要な時だけ他のエージェントへ委譲する軽い仕組みで、エージェント定義そのものの一部として保存される。マルチエージェントは、順序・並列・担当の引き継ぎといった**構成自体を図として保存・版管理・検証したい**場合に使う。エージェント定義を変えずに版固定・予算・実行イベントを付けたいだけなら、サブエージェントで足りることが多い（画面上にも同じ趣旨のヒントが出る）。
> また、エージェント編集画面の「[実行オプション](../04-agents/03-attach-tools-and-more.md#実行オプションこのエージェントだけの実行時機能)」（旧称ハーネス）は1つのエージェントの実行時機能トグルであり、この章のマルチエージェントとは別概念である。

## 画面の場所

左ナビ「作る → **マルチエージェント**」を開く。画面は一覧（Layer 1）と編集（Layer 2）の2段である。

一覧の各行は表示名・`公開名@最新バージョン`・`パターン · 状態`を示し、「**開く**」「**削除**」（確認ダイアログを経由。一覧から消えるだけで保存済みバージョンは履歴に残る）を持つ。保存済みが無い場合は「マルチエージェントはまだありません。」と、各slotに保存済みエージェントが要る旨、そして「**エージェント画面を開く**」リンクが出る。

## パターンを選ぶ

「**新規作成**」を押すと編集画面が開く。左の「**パターン**」から6つから選ぶ（既定は Sequential）。

| パターン（画面表記） | 動き方 | 主な用途 |
|---|---|---|
| Agent as tools | 調整役（Coordinator）が必要な時だけ他のslotへ委譲する | 動的な部分委譲 |
| Sequential | 決まった順に受け渡して仕上げる | 作成 → レビュー → 整形 |
| Concurrent | 同じ入力を独立に並列実行して集約する | 多角的分析・投票 |
| Handoff | 許可された経路で担当を移譲する | 問い合わせの専門部署への転送 |
| Group Chat | 上限round内で発話者を選びながら議論する | 討議・反復レビュー |
| Magentic | Managerが計画・委譲・統合する | 解法が事前に決まらない複雑なタスク |

パターンを切り替えると、slotの初期構成（プリセット）が入れ替わり、既存の割り当ては先頭から位置単位で引き継がれる。

## slotへ割り当てる

1. キャンバス上部の「**内部ID**」「**表示名**」（必須）と「**所有者**」（省略可。空欄ならログイン中の利用者名）を入力する。内部IDは保存済みを開いた場合は読み取り専用になる。
2. 各slotカードの「**Slot名**」「**Slotの目的**」は自由に書き換えられる。
3. 「**保存済みAgentを割り当て…**」のプルダウンから、そのslotを担うエージェントを選ぶ。割り当てるとバージョンが固定され、`{内部ID}@{バージョン}`として表示される（未割当のときは「未割当」）。
4. 「**+ 参加者を追加**」でslotを増やせる。カード右上の「Slotを削除」で減らせるが、パターンごとの最小slot数を下回る削除と、固定先頭slot（Agent as toolsの調整役、Handoffの開始、Magenticのマネージャ）の削除はできない。

キャンバスの形はパターンごとに異なる（Sequentialは一列、Concurrentは分岐して集約、Agent as tools・Group Chat・Magenticはhub&spoke、Handoffは分岐経路）。見た目の違いから、いま組んでいるのがどの方式かが分かるようになっている。

### Concurrentの集約方法

Concurrentを選んだときだけ、右の「パターン設定」に「**集約方法**」が現れる。

| 集約方法（画面表記） | 動作 |
|---|---|
| 機械的に連結 (collect) | 各エージェントの結果をそのまま束ねて返す |
| 投票で決定 (vote) | 多数決で1つの結果を選ぶ |
| Agentで統合 (agent) | 集約役のslotへ割り当てたエージェントが最終回答を作る |

「Agentで統合 (agent)」を選ぶと集約役（Aggregator）のslotが追加され、そこにも保存済みエージェントを割り当てないと保存できない。

## パターン設定（読み取り専用の項目を含む）

右側の「**パターン設定**」には、失敗時の方針（`fail-fast`固定）、最大並列数（`4`固定）のほか、パターンごとのtopology要約（コンテキストmode・話者選択・最大round数など）が並ぶ。ステータス行は次のいずれかになる。

- **previewで実行可能** … 検証・保存が済んでいる
- **検証エラーあり** … 直近の検証で問題が見つかった
- **未検証** … 定義は揃っているが未検証
- **定義が未完成** … 必須項目や未割当のslotが残っている

## 検証して保存する

1. 「**検証**」を押す。slot IDの重複、パターンごとの必須構成（Sequentialの順序、Concurrentの集約役、Handoffの到達可能性、Group Chat・Magenticのround上限など）、参照したエージェントversionの存在、実効副作用を確認する。問題があれば「`path`: `message`」の形で一覧される。
2. 「**バージョンを保存**」を押す。保存できない理由（必須入力の空欄、未割当slot、集約役の未割当）は検証を押さなくてもボタン近くに常時表示される。
3. 保存に成功すると「**保存しました バージョン `x.y.z`**」と出て、下部プレビューの見出しが`{内部ID}@{バージョン}`に変わる。

> 編集途中の内容（パターン・slot構成・内部ID・表示名・所有者・集約設定）はブラウザのローカル下書きへ自動保存される。保存せず他画面へ移ろうとすると確認ダイアログが出て、次に開いたときは「未保存の編集内容があります」バナーから「**復元**」か「**破棄**」を選べる。エージェントの割り当てを変えても元のエージェントは変更されず、保存すると新しいマルチエージェントのバージョンが発行される。

## この画面から試す（preview）

保存後、下部の「**保存済みマルチエージェントのプレビュー**」欄にメッセージを入力し「**previewを実行**」を押すと、チャット画面へ移らずに動作を試せる。結果には状態・応答本文・参加Agent実行の件数が出る。

## チャットから実行する

1. 左ナビの「**チャット**」を開く。
2. 「**チャット対象エージェント**」のプルダウンを開くと、単体のエージェントはそのまま並び、保存済みのマルチエージェントは「**マルチエージェント**」というグループにまとまって`{表示名} · {バージョン} · {パターン}`の形で並ぶ。
3. 依頼を入力して送信する。

実行中は送信ボタンが中断ボタンに変わる（「実行を中断」）。中間の参加エージェント実行はイベント種別とslot IDのチップ列として表示され、最終応答だけが通常の吹き出しになる。マルチエージェントを対象にしている間は画像の添付はできない。

### Handoffの会話再開

`autonomous`をオフにしたHandoffでは、担当エージェントがhandoffせずに応答すると入力待ちになる。コンポーザーのプレースホルダが「**Handoffを続ける返信を入力…**」に変わるので、続きを送ると同じRun・同じ担当・保存済みの会話履歴で再開される。不要なら「**実行を中止**」で打ち切れる。

### Magenticの計画承認

`requirePlanSignoff`をオンにしたMagenticでは、Managerが参加者と指示を選んだ時点でチャットに計画が表示され、「**計画を承認**」「**却下して中止**」ボタンが出る。承認せず入力欄にフィードバックを書いて送信すると「修正依頼」として扱われ、Managerがそれを踏まえて再計画する。

待機状態はcheckpointとして24時間保存される（含まれるのは公開されたやり取り・選択slot・残予算・期限のみで、内部のツール出力やモデルの非公開の思考過程は保存されない）。

## うまくいかないとき

| 症状 | 原因・直し方 |
|---|---|
| 「バージョンを保存」が押せない | 内部ID・表示名の未入力、未割当のslot、Concurrentで「Agentで統合」を選んだ場合の集約役の未割当のいずれか。ボタン近くの理由を確認する |
| 検証でエラーが出る | 一覧の`path: message`を読み、該当slotの割り当てやtopologyの条件（Handoffの到達可能性、Group Chat/Magenticのround上限など）を見直す |
| チャットの選択肢にマルチエージェントが出ない | 保存が済んでいないか、保存後に一覧を開き直していない。左ナビの「マルチエージェント」一覧に状態が出ているか確認する |
| previewが実行できない（read-only以外の副作用） | 参加エージェントの実効副作用が`read-only`でない場合、preview/testでは書き込み系・外部作用は実行されない |

## もっと詳しく

この節は基本の流れをSequentialを例に説明した。役割ごとのエージェントを実際に3つ作り、Sequentialで組み立て、チャットから実行するところまでを画面付きで1本通したい場合は、開発者向けドキュメントの[15 マルチエージェントの操作チュートリアル](../../15-agent-harness-tutorial.md)を参照する。パターンの詳細な仕様（topologyの型・検証規則・REST APIなど）は[14 マルチエージェントビルダー](../../14-agent-harness-builder.md)にある。
