# 02-01. データの登録

この節を読むと、手元の CSV・JSON ファイルや、サーバー側で構成済みのデータベース接続を「データソース」として AgentBlume に登録できるようになる。登録したデータソースは、次章のツール作成でそのまま入力に選べる。

## 1. 「データソース」画面を開く

1. 左ナビ「作る」グループの「**データソース**」を選ぶ。
2. 「**ツールで扱うデータ**」という見出しの画面が開く。「**ファイルをアップロード**」のカードと「**データベース接続**」のカードが並び、下に「**登録済みソース**」の一覧が出る。

## 2. CSV または JSON ファイルを登録する

1. 「**ファイルをアップロード**」カードの「**CSV または JSON ファイル**」欄でファイルを選ぶ。対応する拡張子は `.csv` と `.json` のみ。**1 ファイル最大 5 MB**（超えるとアップロード時にエラーになる）。
2. 「**ソース名**」欄を確認する。空でよい（空の場合はファイル名がそのままソース名になる）。分かりやすい名前を付けたい場合はここに入力する。
3. 「**アップロード**」を押す。
4. 成功すると `"（ソース名）" を登録しました` という緑色の通知が出て、下の「**登録済みソース**」一覧に `CSV · 12.3 KB` のようなサイズ表示付きで現れる。これが登録成功の合図。

ファイルを選ばずに「アップロード」を押すことはできない（ボタンが無効のまま）。`.csv` `.json` 以外の拡張子を選ぶと「**CSV または JSON ファイルを選択してください。**」という赤いエラー帯が出て登録されない。

### 登録できずにエラーが出る場合

アップロード時、AgentBlumeはファイルの中身を実際に読めるか確認してから登録する。次のいずれかに当てはまると赤いエラー帯が出て登録されない。

| 状況 | 何が起きているか |
|---|---|
| ファイルが空 | 中身が 0 バイト |
| ファイルが 5 MB を超える | サイズの上限は UTF-8 換算のバイト数で判定される |
| CSV の 1 行目（ヘッダー行）が空 | CSV は 1 行目を列名として扱うため、ヘッダー行が無いと登録できない |
| CSV に制御文字が混じっている | 文字化けしたファイルやバイナリファイルを間違って選んだ場合に多い |
| JSON として解釈できない | 構文が壊れている（カンマ・カッコの過不足など） |

## 3. 文字コードと列の型について

### 文字コード

アップロードしたファイルは**文字コードを自動判定しない**。ブラウザが標準の文字コード（UTF-8）として読み込む。UTF-8 の CSV に付いていることが多い先頭の BOM（目に見えない印）は自動で取り除かれるので、Excel などで「UTF-8（BOM 付き）」として保存した CSV はそのまま登録してよい。

**Shift-JIS で保存された CSV をそのままアップロードすると文字化けする。** エディタや Excel で一度「UTF-8」として保存し直してからアップロードする。

### 列の型（数値・文字列などの自動判定）

登録時ではなく、そのデータソースをツールで実際に読み込んだときに、列ごとの型が次のルールで自動判定される。

**CSV の場合**、セルの文字列を次の順で判定する。

1. 空文字は「値なし」（null）として扱う。
2. `true` / `false`（この綴りのみ）は真偽値。
3. 数値として読める文字列（`123` `-4.5` など）は数値。
4. `2024-03-31` や `2024-03-31T00:00:00Z` のような ISO 8601 形式の文字列は日付。
5. どれにも当てはまらなければ文字列のまま。

ただし、**同じ列の中に `01000` や `00001` のような先頭がゼロの値が 1 つでもあると、その列全体を数値化せず文字列のまま保つ**（郵便番号・地域コードなどを `1000` のような数値に変えて元へ戻せなくなる事故を防ぐため）。

**JSON の場合**は、ファイルの中の値の型（数値なら数値、文字列なら文字列、真偽値なら真偽値）がそのまま列の型になる。ただし JSON は**オブジェクトの配列**（`[{...}, {...}]` の形）である必要がある。1 個のオブジェクトだけの JSON や、配列がどこかのキーの下にネストしている JSON は、アップロード自体はできてもツールの入力に使おうとしたときにエラーになる。

## 4. データベース（PostgreSQL）から登録する

AgentBlumeは**接続情報（ホスト名・パスワードなど）をブラウザに一切入力させない**。データベース接続はサーバー側の環境変数だけで構成し、画面には構成済みの接続 ID しか出てこない。

1. 「**データベース接続**」カードの「**構成済みの接続**」プルダウンを開く。サーバー側で構成済みの接続だけが `<接続ID> · <ドライバ名>` の形で並ぶ。
2. 使いたい接続を選ぶ。
3. 「**ソース名**」を入れる（空の場合は接続 ID がそのまま使われる）。
4. 必要なら「**既定スキーマ（任意）**」を入れる（空でよい）。
5. 「**接続を登録**」を押す。「**登録済みソース**」一覧に `<ドライバ名> · <接続ID>` の形で現れれば成功。

プルダウンに何も出ない場合は、「DB接続が構成されていません。バックエンドで AGENTCONTEXT_DB_CONNECTIONS を設定してください。」という案内がカードの下に表示される。設定は利用者の画面操作ではできず、AgentBlumeを動かしているサーバー側で環境変数 `AGENTCONTEXT_DB_CONNECTIONS` を設定する必要がある（書き方は [.env.example](../../../.env.example) の該当箇所を参照。パスワードは別の環境変数に分けて指定する仕組みになっている）。設定後はサーバーの再起動が要る。この作業は通常、AgentBlumeを運用している担当者が行う。

登録後、一覧の行にある「**接続テスト**」を押すと、そのデータベースに今つながるかを確認できる。「**接続可能**」と出れば成功、「**利用不可**」の場合は理由が続けて表示される。

## 5. 登録したソースを削除する

1. 「**登録済みソース**」一覧で、削除したい行の「**削除**」を押す。
2. 「**データソースの削除**」ダイアログで内容を確認し、「**削除**」を押す（「**キャンセル**」で取り消せる）。この操作は元に戻せない。

## うまくいかないとき

| 症状 | 原因 | 直し方 |
|---|---|---|
| アップロードした CSV の日本語が文字化けする | ファイルが Shift-JIS など UTF-8 以外の文字コードで保存されている（この画面は文字コードを自動判定しない） | ファイルを一度 UTF-8 で保存し直してから、「**データソース**」画面で登録し直す |
| 郵便番号や地域コードの列が数値になって桁が消えた | 同じ列の値がすべて先頭ゼロなしだった（先頭ゼロが 1 件でもあれば文字列のまま保たれる） | 元データの列に先頭ゼロ付きの値を混ぜられない場合は、ツール側で `型変換` ノードを使って文字列へ戻す（[ツールのノード一覧](../03-tools/03-node-reference.md)を参照） |
| JSON を登録できたのに、ツールで使うと「配列ではない」という趣旨のエラーになる | JSON の最上位がオブジェクトの配列 `[{...}, {...}]` になっていない | JSON ファイルの中身を配列の形に直してから登録し直す |
| 「**構成済みの接続**」プルダウンに何も出ない | サーバー側の環境変数 `AGENTCONTEXT_DB_CONNECTIONS` が未設定 | 運用担当者に [.env.example](../../../.env.example) を参照して設定・サーバー再起動を依頼する（「**データソース**」画面の案内文にも同じ環境変数名が出る） |
| データベース接続の「**接続テスト**」が「利用不可」になる | パスワード用の環境変数が未設定、またはネットワーク・権限の問題 | 表示されたエラー内容を運用担当者に伝える。接続定義自体はサーバー側の設定なので、この画面からは直せない |
