# 02-02. データの下調べ（プロファイル）

この節を読むと、登録したデータの列をAgentBlumeが自動でどう読み取り、「期間の列」「カテゴリの列」「数値の列」「結合できる相手」をどう見つけているかが分かる。ボタンを押して実行する機能ではなく、ツールを組み立てるときに裏側で自動的に働く仕組みだ。

## いつ働くか

この下調べに専用の画面やボタンは無い。データソースを登録したあと、次の場面で AgentBlume が登録済みのデータを読み、列ごとの特徴を自動で計算する。

- ツールを「**テンプレートから作成**」するとき（テンプレートの「期間の列」「値の列」「結合キー」のスロットに、下調べの結果がそのまま選択肢として出る）。
- 「**自動生成 (Factory)**」がデータからツール・エージェントを自動で組み立てるとき。

つまり、この節の内容は「見て使う画面」ではなく「テンプレートやFactoryが賢く動くための下ごしらえ」だと考えるとよい。列の一覧そのものを確認したい場合は、ツール作成画面でそのデータソースをノードに置き、プレビューで実際の行を見るのが早い（詳しくは[03 ツールを作る](../03-tools/README.md)）。

## 期間の列（期間として読める文字列の列）

**その列の空でない値のうち、90% 以上が「期間」として読み取れると、期間の列として扱われる。** e-Stat（政府統計）の CSV によくある「時点」のような列がその代表例。

読み取れる表記の例:

| 種類 | 表記例 |
|---|---|
| 年 | `2024年`、`2024` |
| 年度 | `2024年度`、`FY2024` |
| 月 | `2024年3月`、`2024-03`、`2024/03`、`202403` |
| 日 | `2024年3月31日`、`2024-03-31`、`2024/03/31` |
| 四半期 | `2024年第1四半期`、`2024年度第1四半期`、`2024年1-3月期`、`2024-Q1`、`2024Q1` |
| 半期 | `2024年度上期`、`2024年度下期` |
| 和暦 | `令和6年`、`平成20年4月`（元号は自動で西暦に読み替える） |

1 つの列の中に粒度の違う表記（「2024年」と「2024年3月」など）が混ざっていても、AgentBlumeはそれぞれの行の粒度（年・年度・四半期・半期・月・日）を見分ける。粒度が混ざっている列は、テンプレートやFactoryに「絞り込んでから集計する必要がある列」として伝わる。

読み取れなかった値がある列（90% 未満しか解釈できない列）は、期間の列としては扱われない。

## カテゴリの列（値の種類が少ない文字列の列）

**文字列の列で、値の種類（distinct）が 60 種類以下**なら、カテゴリの列として扱われる。都道府県名や商品カテゴリのような列が典型。この場合、実際に入っている値そのもの（最大 60 件）を一覧として使える。値の種類が 60 を超える列（自由記述に近い列など）はカテゴリの列として扱われない。

## 値の列（集計・計算に使える数値の列）

型が数値と判定された列が「値の列」の候補になる。ただし、**列名に「コード」「code」「id」「_id」「番号」のいずれかを含む数値列は、値の列の候補から除かれる**（地域コードや会員IDのような識別子を、うっかり合計・平均させないため）。列の型がどう判定されるかは[01 データの登録](./01-register-data.md#3-文字コードと列の型について)を参照。

## 結合キーの候補（2 つのデータソースをつなげられるか）

2 つ以上のデータソースを同時に扱うとき（テンプレートで複数のデータソースを選んだときや、Factoryが複数のデータを渡されたとき）、AgentBlumeは「この列とこの列を突き合わせればつなげられそうだ」という組み合わせも自動で探す。候補になる条件は次のとおり。

- 両方のデータソースに**同じ名前**の列があり、型が両立する（片方が数値、もう片方が文字列、のような組み合わせは対象外）。
- どちらの列にも空の値（欠損）が無い（空の値があると、その行が結合で拾えなくなるため）。
- 値の重なりが、種類の少ないほうの列を基準に **50% 以上**ある。

候補として見つかった列は、期間の列 → 列名に「コード」等を含む列 → その他、の順に並ぶ（結合キーとして自然に選ばれやすいものを手前に出すため）。それぞれの組み合わせについて、その列（の組み）が各データソース側で行を一意に決められるかどうかも合わせて判定される。一意でない場合、そのキーで結合すると行が増えることがある。

例: e-Stat のような「時点・地域コード・地域・値・注記」という形の CSV を 2 つ登録すると、「時点」と「地域コード」が結合キーの候補として見つかる（「地域」という名前だけの列や、値に空欄がある「注記」列はキー候補にならない）。

## テンプレート作成での使われ方

ツールを「テンプレートから作成」するとき、テンプレートが要求する「期間の列」「値の列」「結合キー」などのスロットには、ここで説明した下調べの結果がそのまま候補として出る。詳しい画面の使い方は[03 ツールを作る／04 テンプレートから作る](../03-tools/04-from-templates.md)を参照。

## うまくいかないとき

| 症状 | 原因 | 直す場所 |
|---|---|---|
| テンプレートの「期間の列」に選べる列が出てこない | その列の値の 90% 以上が期間として読み取れる表記になっていない | [03 ツールを作る／04 テンプレートから作る](../03-tools/04-from-templates.md) |
| テンプレートの「値の列」に選べる列が出てこない | その列が数値として登録されていない、または列名に「コード」等を含む | [01 データの登録](./01-register-data.md#3-文字コードと列の型について)で型の判定ルールを確認する |
| 2 つのデータソースを結合できる列が候補に出てこない | 列名が完全一致していない、型が合わない、または空の値を含む | 列名・型を揃える（[01 データの登録](./01-register-data.md)を参照） |
