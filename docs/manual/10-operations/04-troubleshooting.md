## 1. 起動できない

| 症状 | 原因 | 直し方 |
|---|---|---|
| `npm install`が失敗する・起動時にバージョン警告が出る | Node.jsが古い（**22.9.0以上が必要**） | PowerShellで`node -v`を確認し、古ければ[nodejs.org](https://nodejs.org/)からLTSを入れ直す |
| `.\scripts\start-dev.ps1`が「用語 … は認識されません」になる | PowerShell 7（`pwsh`）が無い | `pwsh -v`で確認。無ければ入れるか、`npm run build` → `npm start`でビルド起動する |
| 起動時に環境変数のエラーが並んで止まる | `.env`の値が不正 | 表示された変数名を`.env.example`と見比べて直す。シェルに古い値が残っていないかも`$env:AGENTCONTEXT_DB_PATH`のように確認する（シェルの値は`.env`より優先される） |
| 「database schema version N is newer than this build supports」 | 新しいバージョンで作られたDBを古いビルドで開こうとしている | `git pull` → `npm install` → `npm run build`でビルドを最新にする |
| 「プロンプトファイルの検査に失敗しました」で止まる | `AGENTCONTEXT_PROMPTS_DIR`に置いた上書きファイルの一部の節が欠けている | メッセージに出たファイル名と節名を見て、同梱の`prompts/`から該当の節をコピーするか、上書きファイルごと削除する |

## 2. ポートが使用中と言われる

```text
API ポート 3030 は使用中です: … 既存プロセスを停止するか、-ApiPort で別ポートを指定してください。
```

既存プロセスは自動では止めない仕様（他人の作業を巻き込まないため）。次のどれかを行う。

1. 前回の異常終了が原因なら `.\scripts\start-dev.ps1 -Stop` で、このリポジトリ由来のプロセスだけを止める。
2. 別ポートで起動する: `.\scripts\start-dev.ps1 -ApiPort 3031 -UiPort 5174`
3. 誰が使っているか調べて自分で止める: `Get-NetTCPConnection -LocalPort 3030 -State Listen`

## 3. 画面がAPIに繋がらない

「APIサーバーに接続できませんでした」「APIサーバーからJSON以外の応答が返りました」が出るとき。

1. 「**設定**」画面を開き、「**接続**」カードの`API`が「正常」かを見る。「オフライン」なら「**再確認**」を押す。
2. APIプロセスが生きているか`curl http://127.0.0.1:3030/health`（生死のみ）と`curl http://127.0.0.1:3030/ready`（DBまで含めた疎通。失敗時は503）で確認する。
3. `-ApiPort`で既定以外のポートを使った場合、UIのプロキシ設定とずれていないか確認する（両方を`start-dev.ps1`の引数で同時に指定するのが確実）。

一覧が空でエラーも出ていない場合は、単にまだ何も作っていない状態である。[はじめに §10分でサンプルと話す](../01-getting-started/04-first-conversation.md)を試す。

## 4. モデルに繋がらない

まず「**設定**」画面 →「**モデルプロバイダ**」→「**メインモデル**」の「**テスト**」を押す。ここが通れば設定は正しい。

| メッセージ | 原因と対処 |
|---|---|
| 「モデルが未設定です。設定画面でモデルを選ぶか…」 | メインモデルが保存されていない。[はじめに §モデルの設定](../01-getting-started/02-model-settings.md)の手順で保存する |
| 「モデルサーバーに接続できませんでした」 | ローカルならモデルサーバー（LM Studioなど）が起動・ロード済みか確認する。「**ベースURL**」の末尾が`/v1`になっているかも確認する |
| 「モデルサーバーの認証に失敗しました（HTTP 401/403）」 | APIキーが違う・期限切れ。設定画面でキーを入力し直して「保存」→「テスト」 |
| 「モデル実行がタイムアウトしました」 | 応答が遅すぎる。より小さいモデルに替える、質問を具体的にする、チャットの**停止ボタン**で切り上げる |
| 「選択中のモデルはツール呼び出しに対応していません」 | Tool Calling対応モデルが必要。モデル一覧で対応表示を確認して選び直す |
| 「モデルを取得できませんでした」 | 「モデル一覧を取得」が対応していないエンドポイント（Bedrock・Vertexなど）。モデルIDを直接入力すれば進める |

## 5. 実行が失敗する

チャット・動作確認・「ステータス」画面の失敗通知は、**1行目（太字）に次にすることが書かれている**ので、まずそこだけ読めば足りるように作られている。続けて原因・失敗箇所（ツール名・ノード名)・「直しに行く」ボタン（該当のツール画面やエージェント設定を、直すべき箇所が選ばれた状態で開く）が並ぶ。折りたたみの「**技術的な詳細**」には、失敗直前にモデルがツールへ渡した引数など生の情報が出る。

代表的な原因: ツールが未接続、引数の型違い・必須引数の欠落、モデルの応答をJSON化できない、出力が上限バイトを超えた、関数名として不正、MCPサーバーが読み込めなかった、など。実行前に見つけたい場合は、ツール画面の「**呼び出し診断**」、エージェント画面の「**組み込みチェック**」、「**動作確認**」画面の「**ツール診断**」で、実行せずに一覧で検査できる。

ツールの引数・ノード設定に関わる詳しい原因表とメッセージ一覧は[03 ツールを作る](../03-tools/README.md)の各ノード説明、または[19-troubleshooting.md §5](../../19-troubleshooting.md#5-実行が失敗する)を参照。

## 6. データが見当たらない

| 症状 | 原因 | 直し方 |
|---|---|---|
| 再起動したら全部消えた | `AGENTCONTEXT_DB_PATH=:memory:`になっている（使い捨て検証用） | `$env:AGENTCONTEXT_DB_PATH`と`.env`を確認し、ファイルパスに変える |
| 昨日まであったデータが無い | 別のDBファイルを見ている | 起動時のログに出るDBパスが前回と同じか確認する |
| 表やグラフだけ表示できない | セッション成果物（`<DBファイル>.session-artifacts/`）がDBと揃っていない | DBとこのフォルダは常に一緒に扱う。詳しくは[02 データの置き場所とバックアップ](./02-data-and-backup.md) |
| サンプルデータが出てこない | まだ投入していない | 「**チャット**」画面の「**サンプルを読み込んで試す**」、または「**データソース**」画面の「**サンプルを読み込む**」を押す |

## 7. APIキーや暗号鍵が合わない

保存したAPIキーは暗号化され、鍵は既定で`~/.agentblume/secret.key`に置かれる。

| メッセージ | 原因と対処 |
|---|---|
| 「保存済みAPIキーを復号できません。APIキーを再入力して保存し直してください」 | 鍵ファイルが、そのキーを暗号化したときのものと違う（別マシンへDBだけ移した場合など）。「**設定**」画面でAPIキーを**入力し直して保存**すれば直る |
| 「鍵ファイルが読めない、または不正です」 | 鍵ファイル自体が壊れている・パスが違う。再入力では直らない。`AGENTCONTEXT_SECRET_KEY_PATH`と読み取り権限を確認し、元の鍵が無ければ鍵を作り直して全APIキーを再入力する |

詳しくは[02 データの置き場所とバックアップ](./02-data-and-backup.md)、または[運用runbook §3.3](../../17-operations-runbook.md#33-暗号鍵は自動で上書きしない)。

## 8. database is locked が出る

SQLiteに同時に書き込もうとしている。よくある原因は次の3つ。

- **同じDBを2つのプロセスが開いている**（開発サーバーと`npm start`を両方動かしている等）。片方を止める。
- **復元（`--restore`）をサーバー稼働中に実行した。** 復元は必ずサーバーを止めてから行う（[02 データの置き場所とバックアップ](./02-data-and-backup.md#復元はコマンドからのみサーバーを止めて行う)）。
- DBファイルがOneDriveなどクラウド同期フォルダにある。同期対象から外すか、別の場所へ移す。

## 9. 機能が画面に出てこない

| 症状 | 原因 | 直し方 |
|---|---|---|
| データベース接続がプルダウンに出ない | DB接続はサーバー側の環境変数だけで構成する（ブラウザには入力させない設計） | `AGENTCONTEXT_DB_CONNECTIONS`をサーバー側の`.env`に設定して再起動する |
| 業務テンプレートが左ナビに出ない | 「実験的な機能」がオフ | 「**設定**」画面 →「**実験的な機能**」→「**実験的な機能を表示する**」をオンにする（[01 設定画面](./01-settings.md#実験的な機能)） |
| 設計アシスタントのパネルの入力欄が押せない | モデルが未設定、または構造化出力に非対応 | 「**設定**」画面でmainスロットのモデルを選んで再読み込みする（[§4](#4-モデルに繋がらない)） |
| 「Web検索」ノードがノードパレットに出ない | 検索プロバイダの環境変数が未設定（仕様どおり非表示） | 必要なら運用者にTavily等のAPIキー設定を依頼する |
| 監査ログのカードが「ステータス」画面に出ない | 自分のロールに閲覧権限が無い | [03 利用者と権限](./03-users-and-permissions.md)を参照 |
| 未保存の編集が消えたように見える | ブラウザのローカル下書きが自動保存されている | 画面を開き直すと「未保存の編集内容があります」バナーが出るので「**復元**」を押す |

## 10. MCPサーバーのツールが使えない

エージェントにMCPサーバーを付けているのに使われない・「MCPサーバー「…」のツールを読み込めませんでした」と出る場合。**MCPサーバーを解決できなくても実行は止まらず、そのサーバーのツールを抜いて続行する。**

1. 「**MCP**」画面でサーバーの「**テスト**」を押す。失敗するなら設定の問題（コマンドのパス・引数・環境変数、URLとヘッダーを確認する）。
2. テストは通るのに実行で読み込めないなら、エージェント画面の「**組み込みチェック**」で参照名が登録名と一致しているか・有効かを見る。
3. 「MCP画面で保存・テストのボタンが押せない」場合は権限不足（`operate`権限が必要）。詳しくは[03 利用者と権限](./03-users-and-permissions.md#mcpサーバー設定は特別扱い)。
4. 「transport.command is not allowed: …」で接続できない場合は、許可コマンドの一覧を広げる環境変数（`AGENTCONTEXT_MCP_ALLOWED_COMMANDS`）をメッセージの指示どおり設定して再起動する。

## それでも直らないとき

1. 「**ステータス**」画面で実行履歴とエラーを確認する。
2. サーバーの起動ログを確認する（DBパス・読み込んだ設定・警告が出ている）。
3. `curl http://127.0.0.1:3030/health`と`/ready`の応答を確認する。
