# 02 データの置き場所とバックアップ

作ったツール・エージェント・データ・実行履歴がどこに保存されるか、失わないためにどうバックアップを取るかを説明する。読み終えると、日常のバックアップと引っ越し時のバックアップの違いが分かり、自分でバックアップ・保持期限の設定ができるようになる。

> AgentBlumeはローカル実行のアプリで、データはこのPCの中にしか無い。クラウド上の控えは存在しない。バックアップを取らない限り、ディスクが壊れれば全部消える。

## データは3か所に分かれている

| # | 場所 | 既定のパス | 中身 |
|---|---|---|---|
| 1 | **DBファイル** | `~/.agentblume/agentblume.db` | ツール・スキル・エージェント・Wiki・実行履歴・検証資産・暗号化されたAPIキーなど、作ったもの全部 |
| 2 | **アーティファクト置き場** | `~/.agentblume/agentblume.db.session-artifacts/` | チャットで作った表・グラフの実体ファイル |
| 3 | **暗号鍵ファイル** | `~/.agentblume/secret.key` | 保存済みAPIキーを復号する鍵 |

Windowsでの`~`は`C:\Users\<ユーザー名>`である。起動時のログに、実際に使われているDBのパス（`agentblume: database file = …`）が出る。

- **1と2は常に一緒に扱う。** DBファイルだけをコピー・復元すると、表やグラフの実体（2）が失われ、開こうとすると壊れる。
- **3だけは既定で別扱い。** DBファイルが単体で流出しても平文のAPIキーを復元できないようにするためである。この設計のせいで、バックアップに鍵を含めるかどうかという判断が1つ増える（後述）。
- 場所を変えたいときは環境変数`AGENTCONTEXT_DB_PATH`を設定する。詳しい設定方法は[付録 環境変数](../appendix/02-environment-variables.md)を参照。

## `:memory:` を指定すると全データが消える

`AGENTCONTEXT_DB_PATH`に`:memory:`を指定すると、DBがメモリ上だけに置かれ、**サーバーを終了した瞬間に全データが消える**。動作確認・使い捨て検証のための設定であり、通常運用では使わない。

- この状態で動いているときは、「設定」画面に「このワークスペースは揮発ストレージで動作中です。保存したモデル設定は再起動で消えます」という注意が出る。
- 残したいデータがある場合は、`.env`の`AGENTCONTEXT_DB_PATH`をファイルパスにする（または行ごと削除して既定に戻す）か、`:memory:`をやめて再起動する。

## バックアップ

### 画面から取る

1. 左ナビ「運用 → **ステータス**」を開く。
2. 「**バックアップと掃除**」のカードで、「**バックアップ先**」の表示を確認する。
3. 別マシンへ引っ越すときだけ、「**暗号鍵ファイルも含める**」にチェックを入れる（判断は次項）。チェックを入れると「このバックアップは保存済みAPIキーをすべて復号できるようになります。APIキーそのものと同じ厳重さで保管してください。」という注意が赤字で出る。
4. 「**バックアップを作成**」を押す。「バックアップを作成しました: …」と保存先パスが表示され、下の一覧に新しいバックアップが増える。
5. 表示された保存先パスのフォルダを、**別のドライブへコピーする**（同じディスクに置いたままでは「取っただけ」で、ディスクが壊れれば一緒に消える）。

サーバーは動かしたままでよく、実行中のエージェントがいてもバックアップは取れる。一覧の各行には日時・サイズ・スキーマ版・「鍵あり」または「鍵なし」が出る。「未完成のバックアップ（manifestなし）。削除して構いません。」と出た行は、作成中にプロセスが落ちたものなので消してよい。

### コマンドラインから取る

サーバーを止めていても取れるので、タスクスケジューラなどでの定期実行に向く。

```powershell
npm run backup                            # バックアップを作る（鍵は含めない）
npm run backup -- --include-secret-key    # 鍵も含める
npm run backup -- --list                  # バックアップ置き場の一覧
```

### 暗号鍵を含めるかどうか

| | 含めない（既定・日常） | 含める（引っ越し時だけ） |
|---|---|---|
| バックアップ単体の機密度 | APIキーは暗号文のまま | 平文APIキーと同じ。持ち出したら漏洩と同じ扱い |
| 別のPCへ移したとき | APIキーは復号できない（設定画面から入れ直す） | 鍵を手で置けばそのまま使える |

**日常のバックアップでは含めないこと。** 鍵と暗号文を同じフォルダで運ぶと、「DBが流出しても平文キーは守られる」という前提そのものが崩れる。引っ越しのときだけ含め、移し終えたら鍵入りのバックアップは消す。

### 置き場所

既定の出力先はDBファイルの隣である。別ドライブ・外付けディスク・NASへコピーするか、環境変数`AGENTCONTEXT_BACKUP_DIR`で最初から別ドライブに書かせる。古いバックアップは自動で消えないので、ディスクが埋まる前に要らない世代を手で削除する。

## 復元はコマンドからのみ（サーバーを止めて行う）

**復元はAPI・画面からは実行できない。** 稼働中のプロセスはDBファイルを開いたまま握っており、その足元でファイルを差し替えるとデータが壊れるためである。

```powershell
# 1. サーバーを止める（開発サーバーの場合。npm start なら Ctrl+C）
.\scripts\start-dev.ps1 -Stop

# 2. 何があるか確認する
npm run backup -- --list

# 3. 戻す（一覧に出た名前、または絶対パスを渡す）
npm run backup -- --restore backup-20260728-093012345

# 4. 起動して確認する
npm start
```

復元は現用のDBを消さず、`agentblume.db.pre-restore-<時刻>`として退避してから差し替える。「戻したら前より悪くなった」場合は、その退避ファイルを元の名前に戻せば引き返せる。

鍵を含むバックアップから復元しても、**現用の`secret.key`は自動では置き換わらない**。鍵の入れ替えが必要なときだけ手で行う（手順は[運用runbook §3.3](../../17-operations-runbook.md#33-暗号鍵は自動で上書きしない)）。

## 保持期限（retention）

実行履歴（Run）は放っておくと増え続けるため、日数を過ぎたものを自動で掃除する仕組みがある。

| 設定 | 既定 | 内容 |
|---|---|---|
| `payloadDays` | 30日 | 過ぎたRunの入出力を伏せ字にする |
| `traceDays` | 14日 | 過ぎたRunのトレースを伏せ字にする |
| `auditDays` | 365日 | 監査ログを削除する（**30日未満は設定不可**） |

自動実行は24時間ごと。**いますぐ掃除したい**ときは、「ステータス」画面の「バックアップと掃除」にある「**保持期限をいま適用**」を押す。「保持期限を適用しました: Run削除 …件 / payload伏せ字 …件 / …」のように削除件数が出る。

掃除してもDBファイル自体は自動で縮まない（SQLiteは削除領域を再利用するだけ）。ディスクの逼迫は、保持期限の運用とバックアップの古い世代の削除で管理する。

## うまくいかないとき

| 症状 | 原因 | 直し方 |
|---|---|---|
| 再起動したら全部消えた | `AGENTCONTEXT_DB_PATH=:memory:`になっている | `.env`のその行を削除するかファイルパスに変えて再起動する |
| 表やグラフだけ表示できない | DBだけ復元して`<DBファイル>.session-artifacts/`が無い | 復元し直す（DBとアーティファクトは常に一緒に扱う） |
| バックアップが「ENOSPC」で失敗する | 保存先ディスクが満杯 | 古い世代を消すか、`AGENTCONTEXT_BACKUP_DIR`を別ドライブへ向ける |
| バックアップが「EACCES」「EPERM」で失敗する | 保存先に書き込み権限が無い | フォルダ権限を確認するか、書き込めるパスを指定する |
| 「保存済みAPIキーを復号できません」 | DBと鍵ファイルの組み合わせが合っていない | 「設定」画面でAPIキーを入力し直す（詳しくは[03 利用者と権限](./03-users-and-permissions.md)、または[04 困ったとき](./04-troubleshooting.md)） |
| 復元しようとして「the database is currently in use」 | サーバーがまだ動いている | 全部止めてからやり直す（`-Stop`で止まらなければタスクマネージャーで`node`プロセスを確認） |
