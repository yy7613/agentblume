# 環境変数

AgentBlumeの多くの設定は画面（「設定」画面やモデル設定）から行うが、起動前にしか決められないもの（保存先・ポート・認証・外部ファイルの置き場所など）は環境変数で指定する。ほとんどの利用は既定値のままで動くので、変えたいものだけを `.env` に書けばよい。

やり方はクイックスタートのとおり: リポジトリ直下で `copy .env.example .env` してから、必要な行のコメントを外して値を書く。`npm run serve` / `npm start` などの起動コマンドがこの `.env` を自動で読む。1つでも値が不正だと、何がどう不正かをまとめて表示して起動を止める（気づかないまま誤った設定で動き続けることを防ぐため）。

> 全項目と既定値の正確な一覧は [.env.example](../../../.env.example) を参照。本節はそのうち利用者が実際に触りそうなものだけを抜き出して説明する。

---

## 保存先・実行プロファイル

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_PROFILE` | `local` | 実行プロファイル（`local` / `test`）。通常は変更不要 |
| `AGENTCONTEXT_DB_PATH` | `~/.agentblume/agentblume.db` | 作成したツール・スキル・エージェント・Wiki・実行履歴・モデル設定を保存するSQLiteファイルの場所。`:memory:` を指定した場合だけ、プロセスを止めると全データが消える（使い捨て検証用） |
| `AGENTCONTEXT_TENANT_ID` / `AGENTCONTEXT_WORKSPACE_ID` | `local` / `default` | 保存・参照するテナント／ワークスペースの区切り。単一利用者で使う分には変更不要 |
| `AGENTCONTEXT_SAMPLE_DATA` | `false` | `true` にすると起動時にサンプルデータ（商品・顧客・月次売上等）を自動投入する |

## ポートとネットワーク

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_PORT` | `3030` | APIが待ち受けるポート |
| `AGENTCONTEXT_HOST` | `127.0.0.1` | APIが待ち受けるホスト。**認証機能はまだ無いため、ループバック以外（`0.0.0.0` やLAN上のIPなど）へ変える場合は下の `AGENTCONTEXT_AUTH_TOKENS` の設定が必須**になる（未設定なら起動を拒否する） |
| `AGENTCONTEXT_ALLOWED_HOSTS` | 未設定 | 受け入れるHostヘッダのカンマ区切り一覧。単一利用者モードでループバックへバインドしているときだけ、既定で `localhost` 系を要求する（DNSリバインディング対策）。トークン認証を使う構成やリバースプロキシ配下では通常変更不要 |

---

## 認証

単一利用者で使う分には触らなくてよい項目。複数人で共有する場合に設定する（詳しくは [運用と設定 → 利用者と権限](../10-operations/03-users-and-permissions.md)）。

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_AUTH_TOKENS` | 未設定 | Bearerトークンの一覧（JSON配列）。設定すると「トークン認証」モードになり、資格情報の無い相手はAPIを使えなくなる。人ごとに1本発行し、`roles`（`viewer` / `editor` / `publisher` / `operator` / `workspace-admin`）で権限を絞れる。省略時は `editor`（作成・編集・実行はできるが、削除・承認・公開・運用操作はできない） |
| `AGENTCONTEXT_AUTH_MODE` | 未設定（自動判定） | `single-user` か `token` を明示したいときだけ書く。通常は `AGENTCONTEXT_AUTH_TOKENS` の有無から自動で決まるので書かなくてよい |

## ツールテンプレート・プロンプトの置き場所

Tool Builderの「テンプレートから作成」で使うテンプレートや、エージェント・設計アシスタントなどがモデルへ送る指示文は、サーバーのファイルとして置かれている。標準のもの以外を使いたいときに、追加の置き場所を指定する。

- **`AGENTCONTEXT_TOOL_TEMPLATES_DIR`**（既定は未設定 = 同梱の `templates/tools` のみ）— ツールテンプレート（`*.json`）を追加で置くフォルダ。`;` か `:` で区切って複数指定できる。同じidのテンプレートを置くと標準のものを上書きできる。ファイルは実行のたびに読み直すので、サーバーを再起動しなくても追加・修正が反映される。壊れたファイルはそのファイルだけ読み飛ばされ、理由と直し方が「テンプレートから作成」の画面に出る。自分の会社でよく使う構成をテンプレート化して配りたいときに使う。
- **`AGENTCONTEXT_PROMPTS_DIR`**（既定は未設定 = 同梱の `prompts` のみ）— モデルへ送る指示文（Markdown）を追加で置くフォルダ。同じくファイル単位で標準の指示文を上書きでき、再起動なしで反映される。ただし、コードが要求している節が1つでも欠けた上書きファイルを置くと、起動時に「どのファイルの何が足りないか」を示して止まる（黙って挙動が変わるより、気づける方がよいという設計）。手元のモデルの癖に合わせて言い回しを調整したいときに使う。置けるのは運用者だけで、利用者がチャットで入力した文章がここへ書き戻ることはない。

## 実行上限

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_MAX_EXECUTION_ROWS` | `250000` | ツールの結合（join）など、1つのノードが生成してよい行数のサーバー全体の上限。メモリ使用量はこの値にほぼ比例するので、サーバーのメモリに余裕がある場合だけ増やす。ツール側で行数上限を大きく設定しても、実際に効くのはこの値と小さいほう |
| `AGENTCONTEXT_SHUTDOWN_GRACE_MS` | `10000` | サーバーを止めたとき、実行中の実験・Factory実行の完了を待つ上限（ミリ秒）。超えると中断する |
| `AGENTCONTEXT_RETENTION_INTERVAL_MS` | `86400000`（24時間） | 実行履歴などの保持期限（日単位）を自動で掃除する間隔。`0` にすると自動実行を止め、「ステータス」画面からの手動実行だけになる |

## モデル（LM Studio / クラウドAPI互換）

画面のモデル設定を保存していないときだけ使われる既定値。基本は画面から設定すればよいが、複数人で同じ既定を配りたいときに使う。

| 変数 | 既定値 | 用途 |
|---|---|---|
| `LM_STUDIO_BASE_URL` | `http://127.0.0.1:1234/v1` | メインモデル（`main`）スロットの既定の接続先 |
| `LM_STUDIO_MODEL` | 未設定 | 既定のモデルID。未設定だとエージェント実行は拒否される（暗黙で何かを選ぶことはしない） |
| `LM_STUDIO_API_KEY` | 未設定 | Bearerトークンが要る接続先の場合のみ |
| `JUDGE_LM_STUDIO_BASE_URL` / `JUDGE_LM_STUDIO_MODEL` / `JUDGE_LM_STUDIO_API_KEY` | 同上 | 評価モデル（`judge`）スロットの既定。検証画面のLLM採点に使う |
| `ANALYSIS_ASSISTANT_ENABLED` | `true` | Tool Builderの分析設定アシスタント（関数電卓の「AIに式を書かせる」等）を有効にするか |

> APIキーは画面から保存すると暗号化され、ブラウザへ戻されることはない。暗号鍵の置き場所は次の項目。

---

## 秘密値の暗号鍵

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_SECRET_KEY_PATH` | `~/.agentblume/secret.key` | 画面から保存したAPIキーを封緘する暗号鍵ファイルの場所。**DBファイルとは別の場所に置く**（DBだけが流出しても鍵が無ければ復元できないようにするため）。DBファイルをバックアップ・共有するときは鍵ファイルを一緒に運ばないこと |

---

## バックアップ

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_BACKUP_DIR` | DBファイルの隣（例 `~/.agentblume/agentblume.db.backups`） | `npm run backup` や「ステータス」画面の「バックアップを作成」の出力先。1回のバックアップごとに日時付きのフォルダが増える。**暗号鍵は既定で含まれない**ので、別マシンへ複製する場合は鍵ファイルを別途扱う |

## MCPサーバー接続の安全策

外部のMCPサーバーをこのマシン上で起動する設定に関わる安全策。詳しくは用語集の「MCP」、困ったときは [運用と設定 → 困ったとき §10](../10-operations/04-troubleshooting.md)。

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_MCP_ALLOWED_COMMANDS` | `npx,uvx,bunx,cmd` | stdio型のMCPサーバーとして起動を許すコマンド名のカンマ区切り。`node` や `python` を直接起動するサーバーを使うときだけ、そのコマンド名を足す（任意コード実行のリスクがあるため既定には入っていない） |
| `AGENTCONTEXT_MCP_ALLOW_PRIVATE_NETWORK` | `false` | `true` にすると、http接続のMCPサーバーがLAN内（`192.168.*` 等）へ到達することを許す。ループバック（同じマシン上）は常に許可される |

---

## データベース接続（PostgreSQL）

| 変数 | 既定値 | 用途 |
|---|---|---|
| `AGENTCONTEXT_DB_CONNECTIONS` | 未設定 | PostgreSQLへ読み取り専用で接続する定義（JSON）。接続先・読み取りを許すテーブル一覧（`allowedTables`）をサーバー側で決めておくと、「データソース」画面のプルダウンに選択肢として現れる。**接続情報はブラウザには一切入力しない** |
| （`AGENTCONTEXT_DB_CONNECTIONS` の `passwordEnv` が指す変数、例 `REPORTING_DB_PASSWORD`） | 未設定 | DB接続のパスワード。未設定でも起動はするが、その接続は「利用不可」として表示される |

## そのほか（任意）

- **Web検索プロバイダ**（`TAVILY_API_KEY` 等）— ツールに「Web検索」ノードを使わせたいときだけ設定する。必要な値が揃っていないプロバイダはTool Builderの選択肢に出ない。
- **観測（OpenTelemetry）**関連の `AGENTCONTEXT_OTEL_ENABLED` や `OTEL_*` は運用・監視のための開発者向け設定なので、通常は触らなくてよい。詳細は [.env.example](../../../.env.example) を参照。
