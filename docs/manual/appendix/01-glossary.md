# 用語集

本編で使う言葉を、機能をまたいで引けるように1か所にまとめる。各項目は「用語 — 説明」の形で、詳しい章があるものはリンクを添える。

---

## ツールビルダーまわり

**ツール（Tool）** — データを「入力 → 変換 → 出力」の決まった手順で加工する部品。LLMを使わずに動くので、エージェントが呼び出すたびに同じ数字・同じ一覧を確実に返す。キャンバス上にノードをつないで組む。詳しくは `../03-tools/01-what-is-a-tool.md`。

**ノード（Node）** — ツールを構成する処理の最小単位。データを読み込む「入力」、列を絞る・並べ替える・計算するなどの「変換」、統計や相関を出す「分析」、エージェントへ結果を返す「出力」といった役割ごとに種類がある。ノードを線でつないでツール全体の流れを組む。詳しくは `../03-tools/03-node-reference.md`。

**Tool Calling契約** — ツールをエージェントに呼ばせるための取り決め。ツールの公開名・説明文・引数（名前・型・必須かどうか）・返す値の形を、モデルが読めるJSON Schemaとして公開する。ツール画面の「エージェント向けコンテキスト」で中身を確認・編集できる。詳しくは `../03-tools/06-arguments-and-contract.md`。

**設計アシスタント（Design chat）** — ツール作成画面の「設計アシスタント」ボタンから開くチャットパネル。日本語の指示を送ると、いまのキャンバスにノードを追加したり設定を変えたりする（グラフを丸ごと書き直すのではなく、追加・削除・接続変更などの小さな編集を積み重ねる）。適用してもすぐには保存されないので、「この変更を取り消す」で気軽にやり直せる。詳しくは `../03-tools/05-design-assistant.md`。

**データソース（Data source）** — ツールが読み込む元データ。CSV・JSONファイルのアップロード、またはサーバー側で設定済みのPostgreSQL接続がある。データソース自体は加工しない、ツールの入力ノードから参照される素材。詳しくは `../02-data/01-register-data.md`。

**副作用の宣言（read-only / write / external-action）** — ツールが持つ影響の強さの区分。データを読むだけの「read-only」はすぐ実行できるが、状態を書き換える「write」や外部へ作用する「external-action」は実行前に承認が要る。ツールを作るときに宣言する。

**バージョン（SemVer）** — ツール・スキル・エージェント・シナリオなどの資産は保存するたびに版（バージョン）が増える。エージェントは参照するツール・スキルの版を固定するので、後で元のツールを変えても、固定していない限りエージェントの挙動は変わらない。

## エージェントと知識

**エージェント（Agent）** — 利用者と会話し、必要に応じてツール・スキル・Wiki・MCPサーバーを呼び出して答えを作るAI。指示文（システムプロンプト）や持たせる部品をバージョン管理して保存する。詳しくは `../04-agents/01-what-is-an-agent.md`。

**スキル（Skill）** — エージェントに追加で持たせる「専門知識・手順」の資産。責務・発火条件・指示文（instructions）を持ち、依存するツールを版固定して参照する。実行の積み重ねから得た「やり方」を書きためる器でもある。詳しくは `../05-skills-memory-mcp/01-skills.md`。

**Wiki** — エージェントに持たせる「事実・文脈」の知識ベース。名前付きのWikiに業務知識・用語・判断理由をMarkdownページとして書きため、エージェント実行時に関連ページを検索して要約だけを渡す。詳しくは `../05-skills-memory-mcp/02-memory-and-wiki.md`。

**MCP（Model Context Protocol）** — 外部のツール群を提供するサーバーをエージェントへつなぐ標準的な仕組み。MCP画面でサーバーを登録・有効化すると、そのサーバーが公開するツールをエージェントが呼べるようになる。stdioで起動するサーバーはこのマシン上でプロセスを起動する設定であるため、登録・変更には運用者相当の権限が要る。詳しくは `../05-skills-memory-mcp/03-mcp.md`。

## 自動生成・複数エージェント

**Factory（自動生成）** — 目的（やりたいこと）とデータソースを渡すと、ツール・スキル・エージェント・検証用のペルソナ/シナリオを一式自動生成し、疑似ユーザーによる検証結果を見ながら自動で改訂を繰り返す機能。左ナビには「自動生成 (Factory)」と表示される。生成された資産は下書きであり、公開するかどうかは人が判断する。詳しくは `../07-factory/01-factory.md`。

**マルチエージェント** — 複数のエージェントを組み合わせ、1つのエージェントが他のエージェントへ作業を任せられるようにする仕組み。詳しくは `../06-multi-agent/01-multi-agent.md`。

## 検証と品質

**シナリオ（Scenario）** — エージェントの検証パターンの定義。目標（ゴール）・状況設定・会話の上限ターン数・期待して呼ばれるツール・アンケート設問を持ち、疑似ユーザーとの複数ターン会話を実行してエージェントの実力を確かめる。詳しくは `../08-validation/02-scenarios-and-personas.md`。

**ペルソナ（Persona）** — シナリオで会話する疑似ユーザーの人物設定。初心者・専門家・せっかち・懐疑的などの型と、知識レベル・口調・話す量といった属性を持つ。登録すると疑似ユーザー役のエージェントとして実体化され、シナリオから呼び出される。詳しくは `../08-validation/02-scenarios-and-personas.md`。

**データセット / 実験（Dataset / Experiment）** — 「データセット」はエージェントの回答を採点するための事例（入力と、必要なら模範解答）の集まり。「実験」はそのデータセットに対してエージェントを実際に動かし、正誤・LLMによる採点（judge）・所要時間などを集計する実行のこと。詳しくは `../08-validation/03-datasets-and-experiments.md`。

**品質ゲート（Quality gate）** — エージェントの新しい版を公開してよいかを機械的に判定する仕組み。絶対的な基準値や前の版からの悪化幅といった規則（ポリシー）を実験結果に照らして合格・不合格を記録する。合格記録が無いと、その版を公開する申請ができない。詳しくは `../08-validation/04-quality-gate.md`。

**トレース（Run trace）** — 1回のエージェント実行で「モデルへの要求 → ツール呼び出し → ツールの結果 → 最終応答」がどう流れたかの記録。「動作確認」画面で1件ずつ確認できる。
