# モデルの設定

この節では、エージェントが実際に応答できるようにモデルを設定する。**モデルを保存しないとエージェントは1件も応答しない**ので、チャットを使う前に必ず一度は行う。

## 設定画面を開く

1. 左ナビの「**設定**」を選ぶ。「実行環境設定」という画面が開く。
2. ページを下へスクロールし、「**モデルプロバイダ**」まで進む。
3. 「**メインモデル**」と「**評価モデル**」の2つのカードが並んでいる。
   - **メインモデル**（内部名 `main`）… エージェントの実行に使う。**まずこちらを設定する。**
   - **評価モデル**（内部名 `judge`）… 検証画面のLLM採点に使う。後回しでよい。

以下の手順は、この2つのカードのどちらにも同じように使える。

## モデルの選択肢

「**プロバイダ**」のプルダウンから接続先を選ぶ。選択肢は次のとおりで、末尾に環境変数名が付いているものは、画面で保存しなくてもその環境変数でも設定できることを示す。

| プロバイダ | 種類 | 入力するもの |
|---|---|---|
| OpenAI · `OPENAI_API_KEY` | クラウドAPI | モデルID + APIキー |
| Anthropic · `ANTHROPIC_API_KEY` | クラウドAPI | モデルID + APIキー |
| Google · `GOOGLE_GENERATIVE_AI_API_KEY` | クラウドAPI | モデルID + APIキー |
| Microsoft Azure AI Foundry | クラウドAPI | ベースURL（`https://<resource>.services.ai.azure.com/openai/v1`）+ デプロイ名 + APIキー |
| AWS Bedrock | クラウドAPI | ベースURL（`https://bedrock-runtime.<region>.amazonaws.com/openai/v1`）+ モデルID + APIキー |
| Google Cloud Vertex AI | クラウドAPI | ベースURL（プロジェクト・リージョンを含む）+ モデルID + アクセストークン |
| OpenAI互換エンドポイント（LM Studio・vLLM など） | ローカル / その他 | ベースURL + モデルID（APIキーは不要なことが多い） |

> **モデル名のプルダウンは無い。** モデルは提供元で頻繁に入れ替わり、Azure・Bedrock・Vertex では自分でデプロイ・有効化したモデルしか使えないため、固定の一覧を出さない設計になっている。「**モデルID / デプロイ名**」欄に、提供元のコンソールに表示されているIDをそのまま手入力する（欄の下に、そのプロバイダのモデル一覧ページへのリンクが出る）。

## ローカル（LM Studio など）で設定する

1. 「**プロバイダ**」で「**OpenAI互換エンドポイント（LM Studio・vLLM など）**」を選ぶ。「**ベースURL**」に既定値 `http://127.0.0.1:1234/v1` が入る。
2. 「**モデル一覧を取得**」を押す。LM Studio が起動していれば、ロード済みモデルが「モデルID」欄の入力候補になる。
   - 取得できない場合は「モデルを取得できませんでした。」と出る。その場合もモデルIDを直接入力すれば先へ進める。
3. 「**APIキー**」は通常は空でよい（LM Studioは不要なことが多い）。
4. 「**保存**」を押す。「保存しました。APIキー欄はクリアしました。」と出れば成功。
5. 「**テスト**」を押す。`ok (…ms): …` と出れば接続できている。

> **Tool Calling（関数呼び出し）に対応したモデルが必要。** 対応していないモデルを選ぶと、エージェント実行時に「選択中のモデルはツール呼び出しに対応していません」と出る。LM Studio のモデル一覧で "tool use" / "function calling" 対応を確認して選ぶ。

## クラウドAPI（OpenAI・Anthropic・Azure など）で設定する

1. 「**プロバイダ**」から使うサービスを選ぶ。
2. Azure / Bedrock / Vertex を選んだ場合は「**ベースURL**」に雛形が入るので、`<resource>` `<region>` `<project>` の部分を自分の値に置き換える（置き換えるまで保存・取得はできない）。
3. 「**モデルID / デプロイ名**」に、提供元で使えるモデル（Azureならデプロイ名）を入力する。
4. 「**APIキー**」に発行済みのキーを貼る。
5. 「**保存**」を押す。保存に成功するとAPIキー欄は自動でクリアされる。
6. 「**テスト**」を押して接続を確認する。

> 上の一覧に無いサービス（OpenRouter・Groq など）も、OpenAI互換であれば「**OpenAI互換エンドポイント（LM Studio・vLLM など）**」にベースURLとキーを入れれば使える。

## APIキーの扱い

- 保存したAPIキーは**暗号化して保存**され、**ブラウザへ戻されることはない**。保存に成功すると入力欄はその場でクリアされ、以後は「保存済み: `…〈末尾4文字〉`（空のままで維持）」のように末尾4文字だけのヒントが表示される。
- 暗号鍵は既定で `~/.agentblume/secret.key` に置かれる（初回利用時に自動生成）。**この鍵ファイルはデータベースのバックアップとは別の場所で管理し、DBファイルをバックアップ・別マシンへ持ち出すときに一緒に運ばないこと。** 鍵が無いままDBだけを別マシンへ持っていくと、保存済みのAPIキーは復号できなくなる（その場合は該当スロットにキーを再入力すればよい）。
- スロットを未設定のまま残すと、サーバー側の環境変数（`LM_STUDIO_BASE_URL` など）の既定が使われる。画面には「環境変数の既定（LM Studio）を使用中」のように表示される。

## うまくいかないとき

| 症状 | 原因 | 直し方 |
|---|---|---|
| 「モデルが未設定です。設定画面でモデルを選ぶか、環境変数 LM_STUDIO_MODEL を設定してください。」 | メインモデルが保存されていない | 上の手順でメインモデルを保存する |
| 「モデルサーバーに接続できませんでした」 | ローカル: LM Studio が起動していない、モデルが未ロード。クラウド: ネットワーク・プロキシの問題 | ローカルはブラウザで `http://127.0.0.1:1234/v1/models` を開いてJSONが返るか確認する。ベースURLの末尾が `/v1` になっているかも確認する |
| 「モデルサーバーの認証に失敗しました（HTTP 401）」「（HTTP 403）」 | APIキーが違う・期限切れ・宛先違い | 「設定」画面でキーを入力し直して「保存」→「テスト」。宛先（ベースURL・プロバイダ）を変えた場合は、保存済みキーは自動では使われないので新しい宛先向けのキーを入力する |
| 「モデル実行がタイムアウトしました」 | モデルの応答が遅すぎる | ローカルならより小さいモデルに替える、質問を短く具体的にする、チャットの停止ボタンで切り上げる |
| 「選択中のモデルはツール呼び出しに対応していません」 | Tool Calling非対応のモデルを選んでいる | LM Studio のモデル一覧で "tool use" 対応のモデルへ替える |
| 「保存済みAPIキーを復号できません。APIキーを再入力して保存し直してください」 | 別マシンへDBだけを持ってきた等で鍵ファイルが合わない | 設定画面でそのスロットのAPIキーを入力し直して保存する |
