# エージェントを作る

この節では、新規エージェントの基本情報を入力し、システムプロンプトを書いて、最初のバージョンを保存するところまでを説明する。

## 1. 新規作成する

1. 左ナビの「**エージェント**」を開く。
2. 右上の「**新規作成**」を押す。編集画面が開く。

## 2. 定義を入力する

「**定義**」欄に次を入力する。`*`が付いた項目は必須で、未入力のものは保存ボタン近くに「〜が未入力です」として表示される。

| 項目 | 説明 |
|---|---|
| **内部ID** * | 英数字とハイフンなど。例 `support-agent`。**保存すると変更できない**（変更すると別資産として扱われるため、入力欄は保存後は読み取り専用になる） |
| **作業名** * | 下書き段階の作業用の名前。例 `サポートエージェントの下書き` |
| **表示名** * | 画面に出る名前。例 `サポートエージェント` |
| **公開名** * | エージェントを呼ぶときの名前。例 `support_agent`。**他のエージェントからサブエージェントとして委譲される際、`ask_<公開名>` という関数名になる**。英数字・アンダースコア・ハイフン以外を含む、または64文字を超えると委譲できなくなる旨の注意が入力欄の下に出る |
| **所有者** | 省略可。空欄のまま保存すると、ログイン中の利用者名が自動で入る（単一利用者モードでは `Local operator`） |
| **種別** | 「通常」「疑似ユーザー」「評価者」。詳しくは[エージェントとは](./01-what-is-an-agent.md#種別kind) |

## 3. システムプロンプトを書く

右側の「**システムプロンプト**」欄に指示文を書く。必須項目で、文字数がリアルタイムに表示される。

コツ:
- **役割・制約・応答スタイル**の3点を意識して書く（画面のプレースホルダーもこの3点を挙げている）。
- 先に[ツール・スキルを持たせる](./03-attach-tools-and-more.md)を済ませてから「**草案を生成**」を押すと、選択済みのツール・スキル・サブエージェント（と構造化出力の設定）の情報からシステムプロンプトの下書きが自動で作られる。**下書きは保存されない**ので、内容を読んでから必要に応じて手直しし、改めて保存する。
- 下書きの生成は繰り返し押せる。押すたびに現在の選択内容を反映し直す。

## 4. 構造化出力（任意）

回答をあらかじめ決めた形のJSONに固定したい場合だけ使う。

1. 「**構造化出力**」の「**検証済みJSON応答を必須にする**」にチェックを入れる。
2. フィールドごとに「**名前**」「**型**」（`string` / `number` / `integer` / `boolean`）「**必須**」を設定する。「**出力フィールドを追加**」で行を増やせる。
3. フィールド名は空にできず、重複も不可。満たさないと保存できない。

## 5. 保存する

1. 右上の「**バージョンを保存**」を押す。必須項目が埋まり、構造化出力とサブエージェントの委譲基準（後述）が有効な状態でのみ押せる。
2. 保存に成功すると「**保存しました バージョン `x.y.z`**」と出て、保存直後に自動でツール呼び出しの診断が走る（詳しくは[チャットで確かめる・呼び出しを調べる](./04-chat-and-inspect.md#呼び出し診断組み込みチェック)）。
3. 保存前に手動で確かめたいときは、隣の「**組み込みチェック**」を押すと、保存せずに同じ検査だけを実行できる。

> **編集途中の内容は自動保存される**（ブラウザのローカル下書き）。保存せずに他画面へ移ろうとすると確認ダイアログが出る。次に同じエージェントを開いたときは「未保存の編集内容があります」バナーから「**復元**」か「**破棄**」を選べる。

## うまくいかないとき

| 症状 | 原因・直し方 |
|---|---|
| 「バージョンを保存」が押せない | 必須項目の未入力、構造化出力のフィールド名の重複・空欄、サブエージェントの委譲基準の未入力のいずれか。ボタン近くのヒントに理由が出る |
| `ask_<公開名>` の警告が出る | 公開名が関数名として使えない文字を含むか長すぎる。英数字・`_`・`-` のみ、64文字以内に直す（`ask_` の4文字も含めて数える） |
| 内部IDを直したい | 保存済みの内部IDは変えられない。新しいエージェントとして作り直す |
