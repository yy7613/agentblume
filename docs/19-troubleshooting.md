## 1. 起動できない

### `npm install` が失敗する / 起動時に engine の警告が出る

**Node.js のバージョンが古い。** 必要なのは **22.9.0 以上**。

```powershell
node -v
```

22.9.0 未満なら [nodejs.org](https://nodejs.org/) から LTS を入れ直す。`nvm` を使っている場合は、リポジトリ直下の `.nvmrc`（22.19.0）に合わせる。

```powershell
nvm use
```

> なぜ 22.9.0 以上か: 組み込みSQLite（`node:sqlite`）が 22.5.0 以降、`.env` の読み込みに使う `--env-file-if-exists` が 22.9.0 以降で入ったため。

### `.\scripts\start-dev.ps1` が「用語 … は認識されません」になる

**PowerShell 7（`pwsh`）が入っていない**か、Windows PowerShell 5.1 で実行している。

```powershell
pwsh -v
```

入っていない場合は PowerShell 7 を入れる。または開発スクリプトを使わず、ビルドして起動する。

```powershell
npm run build
npm start
```

### 起動時に環境変数のエラーが並んで止まる

起動時に `.env` と環境変数を**まとめて検証**しており、不正な値があると「どの変数の、どの値が、何を期待されているか」を並べて起動を中止する。表示された変数名を [.env.example](../.env.example) と見比べて直す。

**シェルに既に設定されている環境変数は `.env` より優先される。** `.env` を直したのに変わらない場合は、シェル側に古い値が残っていないか確認する。

```powershell
$env:AGENTCONTEXT_DB_PATH
```

### 起動時に「database schema version N is newer than this build supports」

**新しいビルドで作られたDBを、古いビルドで開こうとしている。** データを壊さないよう意図的に起動を止めている。ビルドを最新にする（`git pull` → `npm install` → `npm run build`）か、そのDBに対応するビルドへ戻す。詳細は[運用 runbook §6](./17-operations-runbook.md#6-トラブルシュート)。

## 2. ポートが使用中と言われる

```text
API ポート 3030 は使用中です: … 既存プロセスを停止するか、-ApiPort で別ポートを指定してください。
```

既存プロセスを**自動では止めない**仕様（他人の作業を巻き込まないため）。3つの選択肢がある。

**A. 残留プロセスを掃除する**（前回の異常終了が原因の場合）

```powershell
.\scripts\start-dev.ps1 -Stop
```

このリポジトリ由来と判定できた開発プロセスだけを停止する。

**B. 別のポートで起動する**

```powershell
.\scripts\start-dev.ps1 -ApiPort 3031 -UiPort 5174
```

**C. 誰が使っているか調べて自分で止める**

```powershell
Get-NetTCPConnection -LocalPort 3030 -State Listen | Select-Object OwningProcess
Get-Process -Id <上で出たID>
```

## 3. 画面は出るがAPIに繋がらない

### 「APIサーバーに接続できませんでした」「APIサーバーからJSON以外の応答が返りました」

UI（5173）は動いているが、API（3030）が落ちているか、開発プロキシの向き先がずれている。

1. 「**設定**」画面を開き、「**接続**」カードの `API` が「正常」かを見る。「オフライン」なら「**再確認**」を押す。
2. APIプロセスが生きているか確認する。

```powershell
curl http://127.0.0.1:3030/health
curl http://127.0.0.1:3030/ready
```

- `/health` … プロセスが生きているかだけを見る
- `/ready` … DBへ実際に読み取りを通す。失敗時は `503` と失敗した依存名を返す

3. `-ApiPort` で既定以外のポートを使った場合、UIのプロキシ設定と食い違っていないか確認する。**両方を `start-dev.ps1` の引数で同時に指定する**のが確実。

### 一覧が空のまま

エラーが出ていないなら、単にまだ何も作っていない。[クイックスタート §4](./18-quickstart.md#4-サンプルを読み込んで動かす)のサンプル投入を試す。

## 4. モデルに繋がらない

まず「**設定**」画面 →「**モデルプロバイダ**」→「**メインモデル**」の「**テスト**」を押す。ここが通れば設定は正しい。

### 「モデルが未設定です。設定画面でモデルを選ぶか、環境変数 LM_STUDIO_MODEL を設定してください。」

メインモデルが保存されていない。[クイックスタート §3](./18-quickstart.md#3-モデルを設定する)の手順でモデルを保存する。

### 「モデルサーバーに接続できませんでした」

- **ローカル（LM Studio など）**: サーバーが起動しているか、モデルがロードされているかを確認する。ブラウザで `http://127.0.0.1:1234/v1/models` を開いてJSONが返るか見る。
- 「**ベースURL**」の末尾が `/v1` になっているか確認する。
- **クラウドAPI**: ネットワーク・プロキシ・ファイアウォールを確認する。

### 「モデルサーバーの認証に失敗しました（HTTP 401）」「（HTTP 403）」

APIキーが違う、期限切れ、またはそのプロバイダ向けのキーではない。「設定」画面でキーを入力し直して「保存」→「テスト」。

> 保存済みのキーは**宛先が変わると使われない**。ベースURLやプロバイダを変えた場合は「宛先が保存済み設定と異なるため、保存済みキーは使用しませんでした」と表示されるので、新しい宛先向けのキーを入力する。

### 「モデル実行がタイムアウトしました」

モデルの応答が遅すぎる。

- ローカルモデルなら、より小さいモデルに替えるか、GPUオフロードを見直す。
- 質問を短く・具体的にする。
- チャットの**停止ボタン**（「実行を中断」）で切り上げてから試し直す。

### 「選択中のモデルはツール呼び出しに対応していません」

**Tool Calling（関数呼び出し）対応のモデルが必要。** LM Studio のモデル一覧で "tool use" / "function calling" 対応を確認して選び直す。

同様に、構造化出力が必要な場面（Factory・LLM judge）では **structured output 対応**、画像添付では **vision 対応**のモデルが要る。

### 「モデルを取得できませんでした」

「**モデル一覧を取得**」はOpenAI互換エンドポイントの `/models` を実際に叩く補完機能で、対応していないエンドポイント（Bedrock・Vertex など）では失敗する。**モデルIDを直接入力すれば先へ進める**（使えるIDは提供元のコンソール・ドキュメントで確認する。入力欄の下にリンクがある）。

### 「ベースURLの <…> の部分を置き換えてください」

Azure / Bedrock / Vertex を選ぶとベースURLに雛形が入る。`<resource>` `<region>` `<project>` を自分の値に置き換えるまで保存・取得はできない（雛形のまま送っても不正なURLとして拒否されるため、手前で止めている）。

## 5. 実行が失敗する

チャット・動作確認・ステータスの失敗通知（赤いブロック）は、上から順に**次にすること → 原因 → 失敗箇所 → 直しに行くボタン**の並びになっている。読むのは1行目だけで足りるように作ってある。

1. **1行目（太字）= 次にすること**。例:「ツールの引数の説明を具体的にするか、指示の中でその値を明示してください」
2. **2行目 = 原因**。例:「エージェントがツールを不正な引数で呼び出しました（モデルがツールの必須引数「year」を渡しませんでした）」
3. **「失敗箇所: ツール … · ノード …」** … どのツールの、どのノードで落ちたか。サーバーが特定できたときだけ出る（古い実行履歴には無い）。
4. **直しに行くボタン** … 遷移先を名指しする。
   - 「**ツール「…」のノード「…」を開いて直す**」 … ツール画面でそのツールを開き、失敗したノードを選択した状態にする
   - 「**ツール「…」を開いて直す**」 … ノードまでは分からないとき。引数・関数名の失敗なら「エージェント向けコンテキスト」、出力の失敗なら出力ノードへ寄せて開く
   - 「**エージェント設定を開く**」 … 上限・予算はハーネス設定、未接続ツール・参照切れ・関数名の重複はツール選択、MCP絡みはMCPサーバー一覧へ寄せて開く
   - 「**モデル設定を開く**」「**MCP設定を開く**」
   メッセージの内容から遷移先を決めているので、出ないこともある。
5. **「技術的な詳細」**（折りたたみ） … 生のエラーコードとメッセージ、run ID、**失敗直前にモデルがツールへ渡した引数**。引数の型違い・必須引数の欠落・許可されていない演算子は、ここを見れば原因がほぼ分かる。

代表的なメッセージを挙げる。

| メッセージ | 原因と対処 |
|---|---|
| モデルが存在しないツール「…」を呼ぼうとしました | エージェントにそのツールが接続されていない。エージェント画面の「ツール」で付け直す |
| 1回の実行で使えるツール呼び出しの上限に達しました | 目的を分けて質問する。または実行オプションで上限を広げる |
| モデルとの往復回数の上限に達しました | 指示を具体的にして手順を減らす |
| モデルの応答をJSONとして解釈できませんでした | 構造化出力に対応したモデルへ替えるか、出力項目を減らす |
| ツール「…」は副作用「…」を持つためプレビュー実行できません | プレビューは書き込み系ツールを実行しない。読み取り専用（`read-only` / `session-write`）のツールに差し替える |
| モデルがツールの必須引数「…」を渡しませんでした | ツールの引数の説明を具体的にする。または指示文の中でその値を明示する |
| ツールの引数「…」の型が違います（… が必要、受け取った値: …） | モデルが渡した値が引数の型に合わない。引数の説明を具体的にするか、Agent Input ノードの型を見直す |
| モデルが引数「…」に許可されていない演算子「…」を渡しました | フィルタ条件の「AIに許可する演算子」に無い演算子をモデルが選んだ。引数の説明に使える演算子を書くか、許可する演算子を広げる |
| ツールの出力（… バイト）がエージェント出力の上限（… バイト）を超えました | ツールが返す行が多すぎる。ツール画面で「**行数制限**」ノードで行数を減らすか、出力ノードを「**ワークスペース出力**」に切り替える（成果物の削除では直らない） |
| ツール名「…」は関数名として使えません | モデルへ公開する名前に日本語・空白・記号が入っている。ツール画面の「**エージェント向けコンテキスト**」で英数字・`_`・`-` のみ1〜64文字の名前を設定する |
| ツールの引数定義とAgent Inputノード「…」の列が一致していません | 引数を変えたあと保存し直していない。ツール画面で引数を保存し直す |
| 宣言した出力スキーマがグラフから推論した出力と一致しません | グラフを変えたあと出力スキーマが古いまま。ツール画面で出力スキーマを更新して保存し直す |
| 参照しているツール／スキル／サブエージェント「…@…」が見つかりません | そのバージョンが削除された。エージェント画面で参照を外すか、存在するバージョンへ付け替える |
| MCPサーバー「…」のツールを読み込めませんでした（未登録／無効化中／接続失敗） | 実行は続くが、そのMCPサーバーのツールはモデルに渡っていない。[§10](#10-mcpサーバーのツールが使えない) |
| このセッションは別バージョンのエージェントのものです | 「**新しいチャット**」を押して開始し直す |
| ツール承認の期限が切れました | 同じ指示をもう一度送る |

### 実験（LLM 判定）が起票できない / 判定だけ全部失敗する

| メッセージ・コード | 原因と対処 |
|---|---|
| `JUDGE_MODEL_NOT_CONFIGURED`（409: evaluator profile '…' has judge metrics but no judge model is configured） | 評価プロファイルに judge 指標があるのに、judge スロットにモデルが無い（設定を保存していない、かつ `JUDGE_LM_STUDIO_MODEL` も未設定）。**設定画面で judge スロットのモデルを選んで保存する**。code 指標だけのプロファイルならこのチェックは掛からない |
| `JUDGE_TRACE_UNAVAILABLE`（409: judge rubric '…' requires a tool trace, but dataset '…' contains scenario cases …） | ルーブリックの `tracePolicy` が `required` なのに、データセットに scenario 事例がある。scenario 事例はツール呼び出しの軌跡を持たないので、この組み合わせは走らせても必ず判定失敗になる。**応答本文の `rubric` が示すルーブリックの実行履歴ポリシーを「任意」にする**か、データセットを turn 事例だけにする |
| 実験は `completed` なのに判定レコードが全部 `JUDGE_PROVIDER`「Judge model is not configured; set the judge slot in Settings」 | 起票後に judge の設定が消えた（設定の削除・鍵ファイルの差し替えなど）。設定画面で judge スロットを保存し直して再実行する |

### 実行前に見つける: 組み込みチェック / 呼び出し診断

上の表の多く（参照切れ・関数名・スキーマ不整合・データソース欠落）は**実行しなくても分かる**。実行時には最初に踏んだ1つしか返らないが、診断は各段階を個別に検査して一覧で返す。入口は3つ。

| 入口 | 場所 | 何を検査するか |
|---|---|---|
| 「**呼び出し診断**」 | ツール画面（Tool Builder）のボタン | 保存前の**下書き**に対してツール単位の検査（下記のツール検査）を行う（`POST /tool-drafts/diagnose`） |
| 「**組み込みチェック**」 | エージェント画面（Agent Builder）のボタン | 保存前にエージェント単位の検査と、接続している全ツールのツール検査を行う（`POST /agent-drafts/diagnose`）。**保存が成功したあとにも自動で走る** |
| 「**ツール診断**」 | 動作確認（Inspect）画面 | 保存済みエージェントに対して同じ検査を行う（既存） |

検査結果は項目IDごとに ok / warning / error と原因が出る。原因の文言は実行エラーと同じ表で言語化され、末尾に直し方が付く。

**エージェント単位の検査**

| ID | 見ているもの | error / warning のときにすること |
|---|---|---|
| `skills` | 参照しているスキルのバージョンが存在するか | エージェント画面の「スキル」で参照を外すか、存在するバージョンへ付け替える |
| `tool-versions` | 直付けとスキル経由で同じツールが**別バージョン**で参照されていないか | 直付けツールとスキル側のツールを同じバージョンに揃える |
| `sub-agents` | サブエージェント参照の存在と、委譲ツール名（`ask_<公開名>`）の衝突・形式 | 参照を直す。名前が衝突・不正ならサブエージェントの公開名を英数字・`_`・`-` に変える |
| `function-names` | モデルへ公開する関数名が重複していないか（重複すると後ろのツールは**呼ばれない**） | ツール画面の「エージェント向けコンテキスト」で名前を変えるか、重複するツールを外す |
| `mcp-servers` | 参照しているMCPサーバーが登録済み・有効か | MCP画面で登録・有効化する。使わないならエージェントのMCPサーバー一覧から外す |
| `model` | モデル設定を解決できるか | 設定画面でメインモデルを保存し、「テスト」で疎通を確認する |
| `harness` | ハーネス設定と前提が揃っているか（Web検索なのに検索プロバイダ無し／ファイル記憶なのに参照Wiki無し） | 前提を揃える（検索プロバイダの環境変数・参照Wikiの追加）か、その機能をオフにする |

**ツール単位の検査**（接続ツールごとに1セット）

| ID | 見ているもの | error / warning のときにすること |
|---|---|---|
| `resolved` | 参照しているツールのバージョンが存在するか | エージェント画面で参照を外すか、存在するバージョンへ付け替える |
| `function-definition` | モデルへ渡す function 定義を組めるか（関数名の形式・引数スキーマ） | 「エージェント向けコンテキスト」の名前を英数字・`_`・`-` のみ1〜64文字にする |
| `agent-input` | 宣言した引数（inputSchema）と Agent Input ノードの列が一致するか | ツール画面で引数を保存し直す。引数があるのにノードが無ければ Agent Input ノードを追加する |
| `data-sources` | ソースノードが参照するデータソースを解決できるか | データソース画面でそのデータが残っているか確認し、ソースノードの参照を直す |
| `graph` | 接続と列・型の伝播（列が無い、型が合わない、入力本数が違う 等） | 原因のノードID付きで出る。そのノードの設定または上流の接続を直す |
| `execution` | 設計時サンプル値でのドライラン（実行時にしか出ないノードエラー） | 出たノードの設定を直す（結合の10万行超過、集計の対象列など） |
| `output-schema` | 宣言した出力スキーマとグラフの推論結果の整合（不一致だと**ツール実行後**に落ちる） | ツール画面で出力スキーマを更新して保存し直す |
| `operator-arguments` | 演算子のAI引数化（opBinding）の整合（共通の許可演算子・既定演算子・引数の型） | フィルタ条件の「AIに許可する演算子」「既定の演算子」を揃え、Agent Input の引数を string 型で宣言する |
| `side-effect` | `read-only` 以外は実行前に**承認待ちで止まる**（warning。失敗ではない） | 意図どおりならそのまま。無人で流すならハーネス設定のツール承認をオフにするか、read-only のツールへ替える |
| `state` | ツールが archived / deprecated でないか | archived は外すか後継バージョンへ付け替える。deprecated は付け替えを検討する（warning） |

### 実行が失敗した理由をもっと詳しく見たい

左ナビの「**動作確認**」画面で同じ指示を送ると、モデル要求 → ツール呼び出し → ツール結果 → 最終応答のトレースを1件ずつ確認できる。トークン数・所要時間・呼ばれたツールもここに出る。

過去の実行は「**ステータス**」画面から辿れる。

### ツールのプレビューでエラーが出る

ツールのエラーはモデルとは無関係（ETLエンジンが決定的に実行する）。よくあるもの:

- **「終端ノード(出力)がありません」** … 「出力」から `エージェント出力` などを置いて最後のノードにつなぐ。
- **「グラフの終端ノードは1つだけにしてください」** … 出力ノードが複数ある。1つに減らす。
- **「グラフに循環(ループ)があります」** … 接続が輪になっている。
- **「列が見つかりません: …」** … 上流ノードの出力に無い列を参照している。上流の設定を直すか、参照する列名を変える。
- **「結合キーの型が一致しません」** … `join` の左右でキーの型が違う。`型変換` ノードを挟むか、文字列比較を選ぶ。

---

## 6. データが見当たらない

### 再起動したら全部消えた

**`AGENTCONTEXT_DB_PATH=:memory:` になっていないか確認する。** この値のときだけ、プロセス終了で全データが消える（使い捨て検証用）。

```powershell
$env:AGENTCONTEXT_DB_PATH
```

`.env` 側も確認する。何も指定していなければ既定の **`~/.agentblume/agentblume.db`** に永続化されるので消えない。

> 設定画面に「このワークスペースは揮発ストレージで動作中です。保存したモデル設定は再起動で消えます」と出ていたら、`:memory:` で動いている。

### 昨日まであったデータが無い

**別のDBファイルを見ている**可能性が高い。起動時のログに実際のDBパスが出るので、前回と同じか確認する。`AGENTCONTEXT_DB_PATH` を設定した／外した心当たりがないか見る。

### 表やグラフだけ表示できない

セッションの成果物（表・グラフの実体）はDBの外、**`<DBファイル>.session-artifacts/`** に置かれる。DBだけをコピー・復元すると成果物が失われる。**この2つは常に一緒に扱う。**

### サンプルデータが出てこない

サンプルは「**チャット**」画面のウェルカムカード「**サンプルを読み込んで試す**」、または「**データソース**」画面の「**サンプルを読み込む**」から投入する。既に読み込み済みの場合は「サンプルは既に読み込み済みでした（変更はありません）。」と表示され、何も変わらない（正常）。

---

## 7. APIキーや暗号鍵が合わない

UIから保存したAPIキーは暗号化して保存され、鍵は既定で `~/.agentblume/secret.key`（`AGENTCONTEXT_SECRET_KEY_PATH` で変更可）に置かれる。

### 「保存済みAPIキーを復号できません。APIキーを再入力して保存し直してください」

**鍵ファイルが、そのキーを暗号化したときのものと違う。** 別マシンへDBだけを持って来た場合などに起きる。設定画面でAPIキーを**入力し直して保存**すれば直る。

### 「鍵ファイルが読めない、または不正です。AGENTCONTEXT_SECRET_KEY_PATH を確認してください（APIキーの再入力では復旧しません）」

**鍵ファイル自体が壊れている・読めない・パスが違う。** これは再入力では直らない。

1. `AGENTCONTEXT_SECRET_KEY_PATH` が正しい場所を指しているか確認する。
2. ファイルの読み取り権限を確認する。
3. 元の鍵が失われている場合は、鍵を作り直したうえで**すべてのAPIキーを再入力**する。

手順の詳細は[運用 runbook §3.3](./17-operations-runbook.md#33-暗号鍵は自動で上書きしない)。

> **バックアップ時の注意**: `npm run backup` は既定で暗号鍵を**含めない**。「DBだけが流出しても平文APIキーは守られる」という前提を保つため。別マシンへ引っ越すときだけ `--include-secret-key` を明示的に付ける。含めなかった場合、引っ越し先ではAPIキーの再入力が必要。

---

## 8. database is locked が出る

SQLite に同時に書き込もうとしている。よくある原因:

- **同じDBを2つのプロセスが開いている**（開発サーバーと `npm start` を両方動かしている等）。片方を止める。
- **復元（`--restore`）をサーバー稼働中に実行した**。復元はサーバーを止めてから行う。
- DBファイルがクラウド同期フォルダ（OneDrive等）にある。同期対象から外すか、別の場所へ移す。

詳細と回復手順は[運用 runbook §6](./17-operations-runbook.md#6-トラブルシュート)。

---

## 9. 機能が画面に出てこない

### データベース接続がプルダウンに出ない

DB接続は**バックエンドの環境変数だけ**で構成する（接続文字列やパスワードはブラウザに入力しない設計）。`.env.example` を参考に `AGENTCONTEXT_DB_CONNECTIONS` と、`passwordEnv` で参照するパスワード環境変数をサーバー側へ設定する。設定後はサーバーを再起動する。

### 「Web検索」ノードがノードパレットに出ない

Tavily / TinyFish / Google Custom Search のいずれかに必要な環境変数が揃った場合だけ表示される。**未設定時に非表示なのは仕様。**

### 画像を添付できない

- クリップの「**画像を添付**」は、**マルチエージェントを対象にしているときは使えない**（単体のエージェントを選ぶ）。
- 対応形式は PNG / JPEG / WebP / GIF、**最大2枚・各3 MiB**まで。
- 画像だけでは送信できない。指示文も入れる。
- 画像入力に対応したモデルが必要。

### 「昇格」ボタンが Factory の画面に無い

**仕様。** Factory が生成した資産はすべて draft のまま置かれる。公開・昇格したい場合は「**検証**」画面の品質ゲートから人手で承認する。

### 未保存の編集が消えた

編集中の内容はブラウザのローカル下書きへ自動保存されている（ツール・スキル・エージェント・マルチエージェントの4画面）。次にその画面を開くと「**未保存の編集内容があります**」バナーが出るので「**復元**」を押す。

自動復元しないのは、古い下書きが今の編集を黙って上書きしないようにするため。不要なら「**破棄**」を押す。

> チャット・動作確認・データソース画面には下書き保存は無い。

## 10. MCPサーバーのツールが使えない

エージェントに MCP サーバーを付けているのに、モデルがそのツールを使わない・「MCPサーバー「…」のツールを読み込めませんでした」と出る。

**MCP サーバーを解決できなくても実行は止まらない**（そのサーバーのツールを抜いて続行する）。読み込めなかった事実はトレースの `mcp-server-skipped` 行と、失敗の通知に出る。理由は3つ。

| 表示 | 原因 | 対処 |
|---|---|---|
| （未登録） | エージェントが参照している名前のサーバーが MCP 画面に無い | MCP 画面でその名前で登録する。名前を変えたなら、エージェント画面の MCP サーバー一覧を付け直す |
| （無効化中） | サーバーが「無効」になっている | MCP 画面で有効化する |
| （接続失敗） | 子プロセスが起動しない（stdio）／URL に繋がらない（http） | MCP 画面の「**テスト**」で接続してエラーを見る。コマンドのパス・引数・環境変数、URL とヘッダーを確認する |

確認の手順:

1. **MCP 画面**でサーバーの「**テスト**」を押す。成功するとそのサーバーが公開するツール一覧が出る。ここで失敗するなら設定の問題。
2. テストは通るのに実行で読み込めないなら、**エージェント画面の「組み込みチェック」**（`mcp-servers`）で、参照している名前が登録名と一致しているか・有効かを見る。
3. モデルが「存在しないツール `mcp__<server>__<tool>` を呼ぼうとしました」と出る場合は、そのサーバーが今回の実行で読み込めなかった（上の3つのどれか）か、サーバー側でツールが無くなっている。

### 10.1 更新後に「transport.command is not allowed: node …」で起動しなくなった

2026-09-03 の更新で、起動を許すコマンドの**既定**を MCP サーバーのランチャーだけ（`npx` / `uvx` / `bunx` / `cmd`）に絞った。以前の既定に入っていた `node` / `python` / `python3` / `uv` / `bun` / `deno` / `docker` は外れている。この検査は保存時だけでなく**接続直前にも**当たるので、更新前に保存した `node server.js` のような設定は、接続テストが次のように `ok:false` になり、エージェント実行ではそのサーバーのツールがスキップされる（トレースの `mcp-server-skipped`）。

```text
MCP server "legacy" is not allowed to start: transport.command is not allowed: node. Allowed commands: npx, uvx, bunx, cmd. To allow it, set AGENTCONTEXT_MCP_ALLOWED_COMMANDS=npx,uvx,bunx,cmd,node on the server and restart
```

| 直し方 | いつ |
|---|---|
| メッセージの `AGENTCONTEXT_MCP_ALLOWED_COMMANDS=…` を**そのままサーバーの環境変数に設定して再起動**する | ローカルのスクリプトを `node` / `python` で直接起動するサーバーを使い続ける |
| 設定を `npx` / `uvx` 経由に書き換える（例: `node node_modules/.bin/server` → `npx server`） | 公開パッケージのサーバーなら、許可リストを広げずに済む |

設定そのものは消えていない（一覧に残る）。`node` を足すと `node -e "…"` も通るようになるので、許可リストは**設定を保存できる主体を信頼したうえでの安全策**である（次項）。

### 10.2 MCP 画面で「operate 権限が必要です」（403）と出る

MCP サーバー設定の保存・置換・削除・接続テストは `mcp-server:operate`（**operator / workspace-admin**）が必要になった。stdio の設定はサーバーホスト上で子プロセスを起動する設定で、保存できる主体はホスト上で任意コードを実行できるため（`docs/08-security-auth.md` §3.2）。`AGENTCONTEXT_AUTH_TOKENS` で `roles` を書いていないトークンは `editor` なので設定できない。設定を担当する人のトークンに `"roles": ["operator"]` を付ける。一覧（参照）は従来どおり全ロールで見える。単一ユーザーモード（トークン未設定）は全ロールを持つので影響しない。権限の無いセッションでは画面のボタンが無効になり、同じ理由が表示される。

### 10.3 「transport.env must not override PATH」（400）

`PATH` / `PATHEXT` / `COMSPEC` / `NODE_OPTIONS` / `NODE_PATH` / `NODE_EXTRA_CA_CERTS` / `LD_PRELOAD` / `LD_LIBRARY_PATH` / `LD_AUDIT` / `DYLD_INSERT_LIBRARIES` / `DYLD_LIBRARY_PATH` / `PYTHONPATH` / `PYTHONSTARTUP` / `PYTHONHOME` / `PYTHONWARNINGS` / `RUBYOPT` / `PERL5OPT` / `BASH_ENV` / `ENV` / `PROMPT_COMMAND` / `JAVA_TOOL_OPTIONS` / `_JAVA_OPTIONS` / `SSLKEYLOGFILE` は、許可されたコマンド名のまま**実行される中身を差し替える**変数なので、`transport.env` では上書きできない（大文字小文字を問わず完全一致。`AGENTCONTEXT_MCP_ALLOWED_COMMANDS=*` でも拒否）。`MY_PATH` のような別名は普通の変数として通る。子プロセスは agentblume サーバーの `PATH` を引き継ぐので、必要ならサーバープロセス側の環境変数として設定する。

> MCP サーバーの設定（コマンド・URL・ヘッダー）は現状 SQLite に平文で保存される。認証トークンを含む場合はサーバー側の環境変数で渡すことを検討する。

## それでも直らないとき

1. 「**ステータス**」画面で実行履歴とエラーを確認する。
2. サーバーの起動ログを確認する（DBパス・読み込んだ設定・警告が出ている）。
3. `GET /health` と `GET /ready` の応答を確認する。`AGENTCONTEXT_SOURCE_REVISION` を設定していれば、どのビルドが動いているかも `revision` で分かる。
4. 使い捨ての環境で切り分ける。

```powershell
$env:AGENTCONTEXT_DB_PATH = ':memory:'
.\scripts\start-dev.ps1 -SampleData
```

これで再現しなければ、既存データ側の問題である可能性が高い。
