## 1. 起動できない

### `npm install` が失敗する / 起動時に engine の警告が出る

**Node.js のバージョンが古い。** 必要なのは **22.9.0 以上**。

```powershell
node -v
```

22.9.0 未満なら [nodejs.org](https://nodejs.org/) から LTS を入れ直す。`nvm` を使っている場合は、リポジトリ直下の `.nvmrc`（22.19.0）に合わせる。

```powershell
nvm use
```

> なぜ 22.9.0 以上か: 組み込みSQLite（`node:sqlite`）が 22.5.0 以降、`.env` の読み込みに使う `--env-file-if-exists` が 22.9.0 以降で入ったため。

### `.\scripts\start-dev.ps1` が「用語 … は認識されません」になる

**PowerShell 7（`pwsh`）が入っていない**か、Windows PowerShell 5.1 で実行している。

```powershell
pwsh -v
```

入っていない場合は PowerShell 7 を入れる。または開発スクリプトを使わず、ビルドして起動する。

```powershell
npm run build
npm start
```

### 起動時に環境変数のエラーが並んで止まる

起動時に `.env` と環境変数を**まとめて検証**しており、不正な値があると「どの変数の、どの値が、何を期待されているか」を並べて起動を中止する。表示された変数名を [.env.example](../.env.example) と見比べて直す。

**シェルに既に設定されている環境変数は `.env` より優先される。** `.env` を直したのに変わらない場合は、シェル側に古い値が残っていないか確認する。

```powershell
$env:AGENTCONTEXT_DB_PATH
```

### 起動時に「database schema version N is newer than this build supports」

**新しいビルドで作られたDBを、古いビルドで開こうとしている。** データを壊さないよう意図的に起動を止めている。ビルドを最新にする（`git pull` → `npm install` → `npm run build`）か、そのDBに対応するビルドへ戻す。詳細は[運用 runbook §6](./17-operations-runbook.md#6-トラブルシュート)。

## 2. ポートが使用中と言われる

```text
API ポート 3030 は使用中です: … 既存プロセスを停止するか、-ApiPort で別ポートを指定してください。
```

既存プロセスを**自動では止めない**仕様（他人の作業を巻き込まないため）。3つの選択肢がある。

**A. 残留プロセスを掃除する**（前回の異常終了が原因の場合）

```powershell
.\scripts\start-dev.ps1 -Stop
```

このリポジトリ由来と判定できた開発プロセスだけを停止する。

**B. 別のポートで起動する**

```powershell
.\scripts\start-dev.ps1 -ApiPort 3031 -UiPort 5174
```

**C. 誰が使っているか調べて自分で止める**

```powershell
Get-NetTCPConnection -LocalPort 3030 -State Listen | Select-Object OwningProcess
Get-Process -Id <上で出たID>
```

## 3. 画面は出るがAPIに繋がらない

### 「APIサーバーに接続できませんでした」「APIサーバーからJSON以外の応答が返りました」

UI（5173）は動いているが、API（3030）が落ちているか、開発プロキシの向き先がずれている。

1. 「**設定**」画面を開き、「**接続**」カードの `API` が「正常」かを見る。「オフライン」なら「**再確認**」を押す。
2. APIプロセスが生きているか確認する。

```powershell
curl http://127.0.0.1:3030/health
curl http://127.0.0.1:3030/ready
```

- `/health` … プロセスが生きているかだけを見る
- `/ready` … DBへ実際に読み取りを通す。失敗時は `503` と失敗した依存名を返す

3. `-ApiPort` で既定以外のポートを使った場合、UIのプロキシ設定と食い違っていないか確認する。**両方を `start-dev.ps1` の引数で同時に指定する**のが確実。

### 一覧が空のまま

エラーが出ていないなら、単にまだ何も作っていない。[クイックスタート §4](./18-quickstart.md#4-サンプルを読み込んで動かす)のサンプル投入を試す。

## 4. モデルに繋がらない

まず「**設定**」画面 →「**モデルプロバイダ**」→「**メインモデル**」の「**テスト**」を押す。ここが通れば設定は正しい。

### 「モデルが未設定です。設定画面でモデルを選ぶか、環境変数 LM_STUDIO_MODEL を設定してください。」

メインモデルが保存されていない。[クイックスタート §3](./18-quickstart.md#3-モデルを設定する)の手順でモデルを保存する。

### 「モデルサーバーに接続できませんでした」

- **ローカル（LM Studio など）**: サーバーが起動しているか、モデルがロードされているかを確認する。ブラウザで `http://127.0.0.1:1234/v1/models` を開いてJSONが返るか見る。
- 「**ベースURL**」の末尾が `/v1` になっているか確認する。
- **クラウドAPI**: ネットワーク・プロキシ・ファイアウォールを確認する。

### 「モデルサーバーの認証に失敗しました（HTTP 401）」「（HTTP 403）」

APIキーが違う、期限切れ、またはそのプロバイダ向けのキーではない。「設定」画面でキーを入力し直して「保存」→「テスト」。

> 保存済みのキーは**宛先が変わると使われない**。ベースURLやプロバイダを変えた場合は「宛先が保存済み設定と異なるため、保存済みキーは使用しませんでした」と表示されるので、新しい宛先向けのキーを入力する。

### 「モデル実行がタイムアウトしました」

モデルの応答が遅すぎる。

- ローカルモデルなら、より小さいモデルに替えるか、GPUオフロードを見直す。
- 質問を短く・具体的にする。
- チャットの**停止ボタン**（「実行を中断」）で切り上げてから試し直す。

### 「選択中のモデルはツール呼び出しに対応していません」

**Tool Calling（関数呼び出し）対応のモデルが必要。** LM Studio のモデル一覧で "tool use" / "function calling" 対応を確認して選び直す。

同様に、構造化出力が必要な場面（Factory・LLM judge）では **structured output 対応**、画像添付では **vision 対応**のモデルが要る。

### 「モデルを取得できませんでした」

「**モデル一覧を取得**」はOpenAI互換エンドポイントの `/models` を実際に叩く補完機能で、対応していないエンドポイント（Bedrock・Vertex など）では失敗する。**モデルIDを直接入力すれば先へ進める**（使えるIDは提供元のコンソール・ドキュメントで確認する。入力欄の下にリンクがある）。

### 「ベースURLの <…> の部分を置き換えてください」

Azure / Bedrock / Vertex を選ぶとベースURLに雛形が入る。`<resource>` `<region>` `<project>` を自分の値に置き換えるまで保存・取得はできない（雛形のまま送っても不正なURLとして拒否されるため、手前で止めている）。

## 5. 実行が失敗する

チャットや動作確認でエラーが出た場合、**メッセージの後半に「次に何をすればよいか」が書かれている**。代表的なものを挙げる。

| メッセージ | 原因と対処 |
|---|---|
| モデルが存在しないツール「…」を呼ぼうとしました | エージェントにそのツールが接続されていない。エージェント画面の「ツール」で付け直す |
| 1回の実行で使えるツール呼び出しの上限に達しました | 目的を分けて質問する。または実行オプションで上限を広げる |
| モデルとの往復回数の上限に達しました | 指示を具体的にして手順を減らす |
| モデルの応答をJSONとして解釈できませんでした | 構造化出力に対応したモデルへ替えるか、出力項目を減らす |
| ツール「…」は副作用「…」を持つためプレビュー実行できません | プレビューは書き込み系ツールを実行しない。読み取り専用（`read-only` / `session-write`）のツールに差し替える |
| モデルがツールの必須引数「…」を渡しませんでした | ツールの引数の説明を具体的にする。または指示文の中でその値を明示する |
| このセッションは別バージョンのエージェントのものです | 「**新しいチャット**」を押して開始し直す |
| ツール承認の期限が切れました | 同じ指示をもう一度送る |

### 実行が失敗した理由をもっと詳しく見たい

左ナビの「**動作確認**」画面で同じ指示を送ると、モデル要求 → ツール呼び出し → ツール結果 → 最終応答のトレースを1件ずつ確認できる。トークン数・所要時間・呼ばれたツールもここに出る。

過去の実行は「**ステータス**」画面から辿れる。

### ツールのプレビューでエラーが出る

ツールのエラーはモデルとは無関係（ETLエンジンが決定的に実行する）。よくあるもの:

- **「終端ノード(出力)がありません」** … 「出力」から `エージェント出力` などを置いて最後のノードにつなぐ。
- **「グラフの終端ノードは1つだけにしてください」** … 出力ノードが複数ある。1つに減らす。
- **「グラフに循環(ループ)があります」** … 接続が輪になっている。
- **「列が見つかりません: …」** … 上流ノードの出力に無い列を参照している。上流の設定を直すか、参照する列名を変える。
- **「結合キーの型が一致しません」** … `join` の左右でキーの型が違う。`型変換` ノードを挟むか、文字列比較を選ぶ。

## 6. データが見当たらない

### 再起動したら全部消えた

**`AGENTCONTEXT_DB_PATH=:memory:` になっていないか確認する。** この値のときだけ、プロセス終了で全データが消える（使い捨て検証用）。

```powershell
$env:AGENTCONTEXT_DB_PATH
```

`.env` 側も確認する。何も指定していなければ既定の **`~/.agentblume/agentblume.db`** に永続化されるので消えない。

> 設定画面に「このワークスペースは揮発ストレージで動作中です。保存したモデル設定は再起動で消えます」と出ていたら、`:memory:` で動いている。

### 昨日まであったデータが無い

**別のDBファイルを見ている**可能性が高い。起動時のログに実際のDBパスが出るので、前回と同じか確認する。`AGENTCONTEXT_DB_PATH` を設定した／外した心当たりがないか見る。

### 表やグラフだけ表示できない

セッションの成果物（表・グラフの実体）はDBの外、**`<DBファイル>.session-artifacts/`** に置かれる。DBだけをコピー・復元すると成果物が失われる。**この2つは常に一緒に扱う。**

### サンプルデータが出てこない

サンプルは「**チャット**」画面のウェルカムカード「**サンプルを読み込んで試す**」、または「**データソース**」画面の「**サンプルを読み込む**」から投入する。既に読み込み済みの場合は「サンプルは既に読み込み済みでした（変更はありません）。」と表示され、何も変わらない（正常）。

## 7. APIキーや暗号鍵が合わない

UIから保存したAPIキーは暗号化して保存され、鍵は既定で `~/.agentblume/secret.key`（`AGENTCONTEXT_SECRET_KEY_PATH` で変更可）に置かれる。

### 「保存済みAPIキーを復号できません。APIキーを再入力して保存し直してください」

**鍵ファイルが、そのキーを暗号化したときのものと違う。** 別マシンへDBだけを持って来た場合などに起きる。設定画面でAPIキーを**入力し直して保存**すれば直る。

### 「鍵ファイルが読めない、または不正です。AGENTCONTEXT_SECRET_KEY_PATH を確認してください（APIキーの再入力では復旧しません）」

**鍵ファイル自体が壊れている・読めない・パスが違う。** これは再入力では直らない。

1. `AGENTCONTEXT_SECRET_KEY_PATH` が正しい場所を指しているか確認する。
2. ファイルの読み取り権限を確認する。
3. 元の鍵が失われている場合は、鍵を作り直したうえで**すべてのAPIキーを再入力**する。

手順の詳細は[運用 runbook §3.3](./17-operations-runbook.md#33-暗号鍵は自動で上書きしない)。

> **バックアップ時の注意**: `npm run backup` は既定で暗号鍵を**含めない**。「DBだけが流出しても平文APIキーは守られる」という前提を保つため。別マシンへ引っ越すときだけ `--include-secret-key` を明示的に付ける。含めなかった場合、引っ越し先ではAPIキーの再入力が必要。

## 8. database is locked が出る

SQLite に同時に書き込もうとしている。よくある原因:

- **同じDBを2つのプロセスが開いている**（開発サーバーと `npm start` を両方動かしている等）。片方を止める。
- **復元（`--restore`）をサーバー稼働中に実行した**。復元はサーバーを止めてから行う。
- DBファイルがクラウド同期フォルダ（OneDrive等）にある。同期対象から外すか、別の場所へ移す。

詳細と回復手順は[運用 runbook §6](./17-operations-runbook.md#6-トラブルシュート)。

## 9. 機能が画面に出てこない

### データベース接続がプルダウンに出ない

DB接続は**バックエンドの環境変数だけ**で構成する（接続文字列やパスワードはブラウザに入力しない設計）。`.env.example` を参考に `AGENTCONTEXT_DB_CONNECTIONS` と、`passwordEnv` で参照するパスワード環境変数をサーバー側へ設定する。設定後はサーバーを再起動する。

### 「Web検索」ノードがノードパレットに出ない

Tavily / TinyFish / Google Custom Search のいずれかに必要な環境変数が揃った場合だけ表示される。**未設定時に非表示なのは仕様。**

### 画像を添付できない

- クリップの「**画像を添付**」は、**マルチエージェントを対象にしているときは使えない**（単体のエージェントを選ぶ）。
- 対応形式は PNG / JPEG / WebP / GIF、**最大2枚・各3 MiB**まで。
- 画像だけでは送信できない。指示文も入れる。
- 画像入力に対応したモデルが必要。

### 「昇格」ボタンが Factory の画面に無い

**仕様。** Factory が生成した資産はすべて draft のまま置かれる。公開・昇格したい場合は「**検証**」画面の品質ゲートから人手で承認する。

### 未保存の編集が消えた

編集中の内容はブラウザのローカル下書きへ自動保存されている（ツール・スキル・エージェント・マルチエージェントの4画面）。次にその画面を開くと「**未保存の編集内容があります**」バナーが出るので「**復元**」を押す。

自動復元しないのは、古い下書きが今の編集を黙って上書きしないようにするため。不要なら「**破棄**」を押す。

> チャット・動作確認・データソース画面には下書き保存は無い。

## それでも直らないとき

1. 「**ステータス**」画面で実行履歴とエラーを確認する。
2. サーバーの起動ログを確認する（DBパス・読み込んだ設定・警告が出ている）。
3. `GET /health` と `GET /ready` の応答を確認する。`AGENTCONTEXT_SOURCE_REVISION` を設定していれば、どのビルドが動いているかも `revision` で分かる。
4. 使い捨ての環境で切り分ける。

```powershell
$env:AGENTCONTEXT_DB_PATH = ':memory:'
.\scripts\start-dev.ps1 -SampleData
```

これで再現しなければ、既存データ側の問題である可能性が高い。
