# v51: 自動生成したツールの配置（段組み＋折り返し）

## 問題（実測）

自動生成のどの経路もノードを横一列に並べる: テンプレートは処理の段数ぶん列を作り（`layoutByDepth`）、位置を持たない保存済みツール（Factory 製）は一列に並び（`loadedPositions`）、設計アシスタントは上流の右へ 1 つずつ足す（`designChatPositions`）。実機で生成した 10 ノードのツールは幅 2,740px × 高さ 80px になった。

## 決定

新規 `src/ui/tool-builder/layout.ts`（純関数。`store.ts` から `layoutByDepth`・`loadedPositions`・`designChatPositions`・`freePosition`・配置の定数を移し、`store.ts` は import する）に `layoutWrapped(nodes, edges, options?)` を置く。

1. **列 = 処理の段数**（入力からの最長距離。今の `layoutByDepth` と同じ）。同じ段の複数ノード（結合の 2 本の入力）は縦に並べる。段の中の順は上流の行の平均で決め、線の交差を減らす。
2. **列数で折り返す**。`maxColumns`（既定 4、最低 3。画面は `FlowCanvas` の表示幅 ÷ 列の間隔から決めて渡す）を超えた段は次の帯（band）へ送り、次の帯も**左から右へ**流す（読む向きを変えない）。帯の高さ = その帯で最も縦に積まれた列の高さ + 帯の間隔 60px。
3. **未接続のノード**（エッジを持たない。`agent-input` など）は最上段の「引数の帯」に左から並べ、処理の列を奪わない。
4. 間隔は既存の `PLACEMENT_STEP_X = 280` / `PLACEMENT_STEP_Y = 140` / `ORIGIN` を使う。循環（保存前検査が弾くので本来無い）は最後の列へ置いて必ず終わる。

### 使う場面

| 場面 | 振る舞い |
|---|---|
| テンプレートから作成（`loadTemplate`） | `layoutByDepth` → `layoutWrapped` |
| 保存済みツールを開く（`loadTool`）で**全ノードが位置を持たない** | `layoutWrapped`（一部だけ持つときは従来どおり、欠けたものだけ空き位置へ） |
| 設計アシスタントの応答で、**適用前のキャンバスが空**だった | 返ったグラフ全体を `layoutWrapped` |
| 設計アシスタントで既存のキャンバスにノードを足す | 既存ノードは動かさない。新しいノードは従来どおり上流の右（+220）だが、**右端の上限**（`ORIGIN.x + maxColumns × STEP_X`）を越えるなら、今あるノードの最下端の下の新しい帯の左端へ送る |
| 「**整列**」ボタン（ツール作成画面のキャンバスの上、`FlowCanvas` の操作列） | 全ノードを `layoutWrapped` で並べ直す。押した直後に「整列しました」と「元に戻す」（1 段だけ。次の編集で消える）を出す |

大きく並べ替えた後（上の 1〜3 と整列）は `fitView` で全体を見せる。

## テスト

- `layout.test.ts`: 直線 10 ノード → 4 列 × 3 帯・幅が 4 列ぶん / 結合（2 入力）で合流先が両入力より右・入力は同じ列に縦並び / 未接続ノードは引数の帯 / 帯の高さは最も積まれた列に合わせる / 左から右の向きが全帯で保たれる / `maxColumns` 3 と 6 / 空グラフ / 循環でも終わる / 同じ入力に同じ出力。
- `store.test.ts`: `loadTemplate`・位置の無い `loadTool`・空キャンバスへの設計アシスタント適用が折り返して並ぶ / 既存キャンバスへの追加は既存ノードを動かさず、右端を越える追加は次の帯へ / 整列と元に戻す。
- 実画面（親）: 結合＋計算のツールを開き、幅が画面に収まることを確認する。
